# C6-F4.4 Phase 5 — FIND Native Canonical V2 / Pre-Implementation Contract Audit

## Objective

Promote `find_v1` to native Canonical V2 execution without changing FIND mathematics, RNG streams, or presentation semantics.

## Why FIND is the next target

The current F4.4 bridge already has an explicit V2 RNG capability contract for FIND:

- `130` FIND_SPATIAL_PLACEMENT
- `140` FIND_TOPOLOGY_GENERATION
- `150` FIND_SCANNER_TRAJECTORY
- `160` FIND_TARGET_DRIFT

The legacy corpus and current engine already validate FIND as an active V2 family.

## Existing frozen mathematical contract

FIND uses:

- bounded Lissajous scanner trajectory;
- independent circular target drift;
- discrete per-frame Euclidean `argmin`;
- episodic close-call counting;
- structural RNG consumed before/at setup rather than in frame calculation.

## Native V2 target boundary

Before changing code, audit the real current `FindMechanic.gd` and verify exactly where each parameter now comes from.

Target state:

- `simulation.parameters.find` is authoritative when present;
- legacy `difficulty.find` remains fallback for oracle/legacy compatibility;
- `simulation.seed` and `simulation.rng_version` are authoritative in native V2;
- effective bridge bypasses the legacy V1 -> F3 mechanical projection for `find_v1`;
- no mechanic-specific exception is added to `GeneradorMaestro`.

## Dedicated test required

Create and register:

`tests/C6F4CanonicalV2FindTest.gd`

Required PASS marker:

`[C6F4_CANONICAL_V2_FIND_SUITE] PASS`

The test must prove:

1. migration to Canonical V2 succeeds;
2. direct Canonical V2 execution succeeds;
3. effective runtime input contains no legacy `generation`;
4. effective runtime does not restore `difficulty.find`;
5. native V2 result validates;
6. legacy oracle succeeds independently;
7. effective/oracle equivalence passes;
8. direct V2 result and effective V2 result agree on all frozen result metrics and frame counts;
9. `metadata["distractor_topology"]` remains intact and is not mutated by presentation.

## Critical FIND-specific caution

The historical audit notes that FIND topology is carried in `metadata["distractor_topology"]` and the current presentation layer may not yet render that topology passively. This is a presentation limitation, not a reason to alter the FIND simulation.

## Non-scope

Do not touch:

- RNG algorithms or stream definitions;
- FIND equations;
- `WinningFrameDetector`;
- `SimulationResult`;
- `VideoTimeline`;
- generic presentation composition;
- `build_factory.py`.

## Implementation sequence

AUDIT real FIND source
→ identify exact V2 parameter map
→ implement minimal `setup()` V2-first fallback
→ verify seed/RNG source
→ add dedicated V2 test
→ add `find_v1` to native bridge set
→ run full regression
→ run production batch
→ freeze Phase 5.

## Acceptance target

No simulation output may change between the legacy oracle and native Canonical V2 except for fields already explicitly defined as non-semantic transport metadata.

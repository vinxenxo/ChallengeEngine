# C11-C 2.17.6 — Challenge Capture Contract Audit

## Decision

The Challenge producer must **not** change the Godot viewport from the frozen 540×960 presentation canvas to 720×1280 merely to obtain a 720×1280 delivery file.

The safe path is:

```text
Frozen Challenge runtime
    ↓
Godot Movie Maker source: 540×960
    ↓
FFmpeg post-capture scale
    ├── REVIEW_720 → 720×1280
    └── META_REELS_FINAL_V1 → 1080×1920
```

This is not a gameplay change and does not alter the frozen Challenge mechanics, RNG, `SimulationResult`, `winning_frame`, `close_calls`, or declared timeline.

## Important legacy-definition finding

`CHALLENGE_008` and `CHALLENGE_009` contain a legacy `video.total_duration = 11.0`, while their four declarative phase durations sum to 12.0 s.

C11-A.1 evidence uses 12.0 s / 720 frames. Therefore the current producer must derive `--quit-after` from:

```text
hook_duration + game_duration + reveal_duration + cta_duration
```

and must not privilege the stale `total_duration` field.

## Why changing only the viewport is not equivalent

C11-B defines the logical Unified Social Frame as 540×960 and maps the 1080×1920 simulation into the 540×960 BodyRegion through `CoordinateMapper`.

The frozen `Main.tscn` contains a fixed 540×960 `UnifiedSocialFrame`. The historical Challenge path does not establish the same explicit 4/3 whole-composition transform that C11-C Visual Loops/Drills use for their 720×1280 physical output.

Therefore replacing the native Challenge viewport with 720×1280 would be a different rendering configuration, not merely a file-size change. The deterministic mechanics do not read Godot viewport APIs, so the change is not expected to alter their mathematics, but the presentation geometry is not contract-proven to remain identical.

## 2.17.6 producer boundary

This overlay changes only production orchestration:

- native Challenge Movie Maker capture remains 540×960;
- delivery scaling occurs after capture with FFmpeg/Lanczos;
- C7 PCM is passed to FFmpeg explicitly as `s16le`, 44.1 kHz, mono, matching `AudioExportBridge`.
- a stale C11-C `override.cfg`, when present, is temporarily quarantined and restored;
- process launch continues through `ProcessStartInfo` so `--config=` reaches `OS.get_cmdline_user_args()`;
- failed runs retain the complete diagnostic scratch directory;
- timing is derived from the four canonical video phases.

No `challenges/*.json`, `Main.tscn`, `project.godot`, mechanics, execution pipeline, RNG, or presentation truth code is modified.

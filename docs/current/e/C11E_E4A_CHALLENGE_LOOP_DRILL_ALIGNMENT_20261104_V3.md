# C11-E — Family Presentation, Editorial and Music Alignment — V3

## Shared architecture

E1 is the shared request and intent orchestration layer. It seals source/selector, gameplay/music seed domains, delivery profile, request-scoped options and effective editorial identity. GUI and CLI must converge on that service. E1 does not replace family-specific presentation or music.

## Challenge

Challenge retains the C `HOOK/GAME/REVEAL/CTA` model and source timeline. `show_hook_countdown` is a Challenge-only request option; omission defaults ON. D's editorial adapter consumes title/subtitle in HEADER/HOOK and `call_to_action` in FOOTER/CTA by source-timeline windows and applies the existing C11-C `C11CVisualEditorialLayer`. The C Challenge binder and native UI are not modified. The adapter deep-copies the live render model for ON/OFF option behavior; it suppresses native CTA only while a populated D CTA owns the footer. OFF is not claimed to erase countdown/hook pixels already baked into an existing C MP4.

`language` is metadata-only. Empty fields are suppressed. `player_name` and `challenge_label` remain blocked pending separate geometry authority. Visual placement stays unapproved until independent/operator review.

## Visual Loop and Visual Drill

Loop retains its grammar/variant binder, timing and existing C11-C family music. Drill retains its type/tier binder, timing/END_CTA precedence and existing C11-C family music. They do not receive Challenge's `presentation_options.show_hook_countdown` field. No family shares a binder or music seed domain merely because E1 orchestration is common.

## Protected boundary

Do not modify C11-C binder/runtime/mechanics/RNG, `SimulationResult`, `winning_frame`, `close_calls`, `RenderedFrameStream`, `FrameSnapshot.custom_data`, `core/audio`, the frozen C manifest or the five GUI surfaces. One D-only Challenge test adapter is not production dispatch. C11-C remains production authority; `release_authority=NONE` until E8 and separate approval.

# E4B Loop D-only Consumer Implementation Blueprint — V1

**State:** `BLUEPRINT_ONLY_NOT_AUTHORIZED_FOR_IMPLEMENTATION`.

## Objective

Prepare a single D-only consumer at the existing D boundary so the future C11-E Producer can compose the four D9.8 Loop editorial fields around the unmodified C11-C family visual output and use the existing C11-C family music path. This is the intended path toward eventual C→D factory cutover; it is not current renderer authority.

## Prerequisites — must be completed first

1. Current-hash operator decisions on A.1 shared semantic regions, A.3 Loop/Drill field windows and C11-E Loop composition proposal. Record exact SHA-256, decision, rationale, operator and date in a new versioned D-owned decision record; run focused positive/negative tests.
2. D9.8/D9.9 semantic reconciliation. D9.9 plan-only is proven, while D9.8 remains ACTIVE_MODEL_ONLY / PENDING_D9_9_UNIVERSAL_REQUEST_ADAPTER. A separate executable-plan/D4 acceptance is required before any renderer-native input.
3. D family binding scope review. Historic exact-selector materializer is Geometric Waves-only. Trace the existing D request-scoped binding path for all other families; no copy/paste of geometric binders, no removal of selector guards, no parallel binder.
4. D4.8 and all downstream renderer/input authority remain blocked. No implementation that writes native renderer input before explicit approval.

## Target architecture (conditional)

```text
Existing Producer GUI / CLI
    -> D9.9 canonical request
    -> D9.10 editorial bridge
    -> one D-owned Loop family adapter at existing boundary
    -> family-specific request-scoped selector/binding
    -> silent C11-C visual family output (source frame preserved)
    -> D outer editorial compositor
    -> existing C11-C family music path, separately seeded
    -> H.264 stream-copy mux
    -> QA / human review
```

The diagram is a future target only. E1 currently leaves Loop fields `NOT_CONSUMED_E1` and family adapter `NOT_CONNECTED_E1`; no runtime dispatch is implied.

## Rendering/composition invariants

- Preserve the entire original C11-C frame and all family-native content: identity, grammar, metrics, palette, cycles, timeline, Matrix transition and source frame order.
- Editorial title/subtitle/CTA are outer D bands only if A.1/A.3/composition are approved. Language remains metadata. Four keys remain canonical; blank value semantics are explicit and cannot silently omit keys.
- `REVIEW_720` is current target profile metadata, not renderer baseline approval.
- Test actual font file availability, shaping, glyph fallback, Unicode NFC, line wrapping, overflow, clipping, contrast and legibility in actual target compositor after approval. Static geometry tests are insufficient.
- No changes to `C11CVisualEditorialLayer`, `UnifiedSocialFrame`, C11-C family scenes/prototypes, binders, timelines, Matrix, RNG or music generator.

## Seed/music separation and A/V

- Visual generation uses `request.seed` only.
- Existing C11-C family music generation uses `request.music_seed` only, retaining family/profile/grammar selection. No D3 V5 substitution for Loop.
- Do not invoke family music generator until later A/V approval (B.1 and D.1), then verify A/B repeatability, independent C music-seed difference, PCM/master/audio QA, AAC mux, H.264 stream-copy identity and A/V sync.
- E4B visual-only and A/V gates require separate test authorization and must remain TEST_ONLY.

## GUI/CLI requirement

Every future adapter/compositor path must be callable through the existing Producer GUI and CLI using one canonical service/helper. No sixth surface, second Producer, parallel binder or GUI-only code path. GUI and CLI must share request, plan and output identities wherever semantics require equality, with provenance IDs compared appropriately.

## Exit criteria

Only after current policy decisions, family binding proofs, D-only consumer positive/negative tests, all-family visual validation, audio/timebase decisions, A/V QA and user review may E4B close. E4C Drill then follows, then E5 → Smoke18 → Matrix101 → E8. No production promotion until separate freeze/promotion authority.

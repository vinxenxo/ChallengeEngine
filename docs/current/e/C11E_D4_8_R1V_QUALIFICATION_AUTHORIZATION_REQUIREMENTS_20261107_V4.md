## 2. Exact permitted encoder call

Only the already-existing C11-C `-NoSound` branch inside the five pinned launchers may call:

```text
ffmpeg -y -hide_banner -loglevel error -i <AVI> -an -c:v libx264 -preset fast -crf 18 -pix_fmt yuv420p -movflags +faststart <MP4>
```

The AVI is a transient OS-temp intermediate; the pinned launcher must remove it in its existing `finally` path. The runner checks each unique AVI filename prefix before and after each invocation. The silent MP4 is the immutable C-source artifact for R1V evidence, not a D-composited deliverable.

## 3. Hard prohibitions

No FFmpeg filter graph, scale, fps conversion, subtitles, overlays, concat, GIF, derivative encode, audio input, mux or transcode beyond the exact native silent C11-C encode above. No music generation, PCM, D3, D compositor, D9.10 renderer-consumer dispatch, production renderer activation, production delivery, longform, Smoke18/Matrix99, freeze, promotion or release.

The runner passes only R1P `request.seed` gameplay seed. It never passes `music_seed`. It uses only the five exact selector/launcher/prototype/scene tuples fixed in policy V2. Each selector has two labels A/B, a unique run-id-bearing output tag, and a separate new output root.

## 4. Filesystem safety

All ten output-root leaf paths must be absent before the first launch. The ten deterministic C11-C temp-silent MP4 paths must also be absent. The ten run-tagged temporary AVI filename patterns must be empty. The runner never cleans, reuses or overwrites these locations. A collision aborts before the first launch.

The runner snapshots the pre-run `override.cfg` existence and bytes. It only restores/removes the exact known temporary bytes generated by the pinned C11CMovieCapture helper. If the file contains unexpected bytes, it leaves those bytes untouched and fails closed. It also checks that the helper's unique temporary backup files do not leak.

All 61 source pins (30 R1P, 28 transitive C11-C, 3 Option C) and the D4.8 production policy are checked before capture, after each launcher and at finalization.

## 5. Acceptance criteria

Technical qualification requires:

- 10/10 launcher exit codes zero and each own C11-C PASS marker;
- five A/B pairs with equal frame count, complete PTS sequence, time base, geometry and per-frame decoded pixel hash array;
- 720×1280, 30 FPS, `yuv420p`, one video stream, zero audio streams;
- actual FFprobe frame count equal to the R1P timing descriptor (descriptor is a consistency check, not proof);
- strictly increasing PTS at 1/30-second intervals within 10 μs;
- every source MP4 byte-identical before/after read-only inspection;
- 61/61 source pins before/after each launch and at finalization;
- no retained AVI, GIF, WAV, silent-temp MP4 or override backup residue;
- captured stdout/stderr hashes, executable pins, report, inventories, per-frame hashes and evidence ZIP.

A technical PASS remains `PENDING_OPERATOR_VISUAL_REVIEW`. It is not a production gate closeout.

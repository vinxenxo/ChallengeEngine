## 2.19.6 workstation defect and repair

The 2.19.6 worker pool correctly created independent temporary Godot project roots, but it intentionally excluded the source `.godot` directory. A fresh worker therefore lacked Godot's generated global script class cache. `UnifiedSocialFrame.gd` references the named class `PresentationProfile`; without the cache Godot emitted `Could not find type "PresentationProfile" in the current scope`, then `UnifiedSocialFrame` failed to load. Movie Maker could still emit frames from the partially loaded runtime, producing gray/empty videos.

The consolidated repair is:

1. Copy the repository into one private worker root per slot.
2. Exclude source `.godot` and `override.cfg` so no generated project state is shared.
3. Before any capture, run exactly one worker-local Godot bootstrap:

```text
godot.exe --headless --editor --path <worker-root> --audio-driver Dummy --quit
```

4. Require `<worker-root>/.godot/global_script_class_cache.cfg` to exist and contain `PresentationProfile`.
5. Only after all worker roots are prepared, launch Movie Maker jobs concurrently.

The bootstrap phase is sequential preparation, not capture serialization. `Workers=7` remains the actual runtime concurrency contract.

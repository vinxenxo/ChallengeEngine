# C11-C 2.19 — Permanent Engineering Rules

1. `ChallengeEngine-C11-C2.16.9 FROZEN.zip` is the behavioral oracle.
2. Never reopen C11-B simulation truth, RNG ownership/algorithm, `SimulationResult`, `winning_frame`, `close_calls`, `WinningFrameDetector`, `RenderedFrameStream`, C7 audio ownership/contracts, C9 semantics, or logical 540x960 geometry without an explicit checkpoint.
3. `c11c-suite/` is the only active Suite surface; `c11c-studio/` is historical only.
4. Every new executable test/runner must have a Suite route.
5. PowerShell executable files obey the encoding/parse contract: one required BOM, ASCII-safe punctuation, and safe interpolation around colons.
6. Under `Set-StrictMode`, optional JSON properties are inspected through `.PSObject.Properties[...]` before dereferencing.
7. Preserve objects required by later consumers; do not pipe them to `Out-Null`.
8. Functions intended to return structured objects must keep diagnostic output out of the return pipeline.
9. Resolve repository root from `$PSScriptRoot`, not the caller's current directory.
10. Worker review uses private temporary Godot roots, private `.godot` state and per-worker class-cache bootstrap.
11. No shared `override.cfg`, no global mutex and no serial fallback; `Workers=7` requires observed concurrency > 1.
12. Validators consume the real manifest schema. Support explicit `output_mp4`, explicit `mp4`, or deterministic sibling derivation only where that is the canonical schema behavior.
13. Legacy/current family identifiers must use an explicit crosswalk. Do not assume editorial keys equal historical technical IDs.
14. Do not mutate authoritative Challenge JSON merely to satisfy a faulty QA assertion.
15. Separate generation from validation; repair metadata/evidence without rerendering complete media when possible.
16. Repository cleanup is dry-run first; conflicts are archived rather than silently overwritten.
17. Process-level transient faults may be retried only under an explicit, bounded contract. The logical runner recognizes only signed/unsigned `0xC06D007F` as a retryable startup/runtime exit; deterministic FAIL markers and other failures remain hard failures.
18. Repair method: FAIL -> reproduce -> locate exact file -> compare with 2.16.9 -> minimal change -> targeted test -> regression -> acceptance evidence -> freeze.

# C11-C 2.19 — Permanent Engineering Rules

1. `ChallengeEngine-C11-C2.16.9 FROZEN.zip` remains the behavioral oracle for protected historical engine truth.
2. Never reopen C11-B/C simulation truth, mechanics, RNG ownership/algorithm, `SimulationResult`, `winning_frame`, `close_calls`, `WinningFrameDetector`, `RenderedFrameStream`, C7 audio ownership/contracts, C9 semantics or logical 540x960 geometry without an explicit checkpoint.
3. `c11c-suite/` is the only active Suite surface; `c11c-studio` is historical only; the misspelled `c11c-maintenace` alias must not remain active.
4. Every new executable test/runner gets a Suite route and a direct console path.
5. PowerShell files obey the repository parse/encoding contract and must be checked with Windows PowerShell 5.1 before expensive execution.
6. Under `Set-StrictMode`, optional JSON properties are inspected through `.PSObject.Properties[...]` before dereferencing.
7. Preserve objects required by later consumers; do not pipe structured return objects to `Out-Null`.
8. Functions intended to return structured objects keep diagnostics out of the return pipeline.
9. Resolve repository roots from `$PSScriptRoot`, not the caller's working directory.
10. Review `Workers=7` means genuine concurrency with private temporary Godot roots and private `.godot` state.
11. No shared `override.cfg`, global mutex or serial fallback is accepted as a substitute for worker isolation.
12. Validators consume the real manifest schema: explicit `output_mp4`, explicit `mp4`, or canonical sibling derivation where supported.
13. Historical/backend identifiers and editorial family names use explicit crosswalks; never infer equality by string similarity.
14. Never mutate authoritative Challenge JSON just to satisfy a faulty QA assertion.
15. Separate generation from validation; prefer metadata/evidence repair over rerender when the media is already valid.
16. Cleanup is dry-run first, allowlist-based where possible, and conflicts are archived rather than silently overwritten.
17. `reset_c11c_artifacts.ps1` is destructive maintenance, not a routine review/freeze step.
18. The freeze package is produced only by `create_c11c_freeze_zip.ps1` after full acceptance and its own dry-run.
19. Repair method: FAIL → reproduce → locate exact file → compare with the protected baseline → minimal change → focused test → regression → acceptance → freeze.

# C11-C 2.19.12 - C11-A.1 canonical producer closure V16

## Root cause

The active 2.19.14 source tree contains a zero-byte root `build_factory.py`. Python therefore returns exit code 0 without executing a factory, creating telemetry, media or a manifest.

## Repair

Historical C11-A.1 orchestration now delegates to the already-canonical Challenge producer:

`tools/prototypes/c11c_bulk/run_c11c_challenge_production.ps1`

The producer captures the Challenge natively at `540x960`, creates the requested `MASTER_1080` delivery at `1080x1920`, writes `production_manifest.json` and preserves `godot.log`/source AVI evidence. The A1 runner then validates those real artifacts and creates a compatibility manifest matching the historical A1 consumer contract.

## Compatibility manifest

`runs/<run>/artifacts/<CHALLENGE_ID>/<CHALLENGE_ID>_manifest.json` is an adapter, not a second renderer. Its `artifacts.final_video` and `artifacts.raw_video` entries are relative to the adapter manifest and point to the real producer outputs. Telemetry is read from the actual `[TELEMETRY_JSON]` emitted by Godot.

## Fast diagnostic acceptance

Run exactly one case:

```powershell
.\FULL_ACCEPTANCE_C11C_2.19.12_A1_SINGLE.ps1 -ChallengeId CHALLENGE_001 -Seed 12345
```

This does not run the 137-suite corpus, the 54-run A1 matrix, the A1 finalizer, the retrocompatibility gate, C10 physical gates or the 52-video review.

The single-run acceptance is a diagnosis/iteration gate. The formal freeze still requires the normal `FULL_ACCEPTANCE_C11C_2.19.12.ps1` to return PASS.

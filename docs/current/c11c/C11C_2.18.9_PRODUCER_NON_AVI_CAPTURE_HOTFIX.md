# C11-C 2.18.9 — Producer Non-AVI Capture Hotfix

## Scope

Post-freeze additive production repair. C11-B simulation truth, RNG ownership, SimulationResult, winning_frame, close_calls, WinningFrameDetector, RenderedFrameStream, C7 ownership, C9 semantics and logical 540x960 geometry remain untouched.

## Visual Drill capture

The single-Visual-Drill Producer no longer depends on either AVI or a PNG frame sequence. Godot Movie Maker records a single temporary `.ogv` container in `artifacts\scratch\c11c_producer_drill\<run>`. FFmpeg then converts only the video stream into the canonical H.264 source MP4; Producer-generated family music is muxed separately afterwards.

Godot 4.7 documentation identifies OGV/Theora+Vorbis as a built-in MovieWriter and notes that OGV can be recorded by editor builds. The project uses the Windows Godot 4.7.1 Mono editor build, matching that capture mode. citeturn517677search1turn517677search6

The `.ogv` is strictly scratch-only and is removed with the temporary stage after success or failure. No AVI or PNG sequence is retained or exposed by the Producer GUI.

## Robustness

The runner also parses Godot's `Done recording movie at path:` completion line and prefers the reported existing path before waiting for file stability. This makes the handshake tolerant of path normalization by the Movie Maker backend.

- Producer self-test: OGV capture, no AVI, no PNG sequence, resolved Godot executable and 0.9.5 revision.

## Expected result

A single Visual Drill production produces the same final MP4/delivery artifacts as before, but the temporary Movie Maker intermediary is one `.ogv` file rather than AVI or hundreds of PNG files.

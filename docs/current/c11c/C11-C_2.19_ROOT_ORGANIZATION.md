# C11-C 2.19 — Repository Root Organization

The repository root is reserved for project entrypoints and governance metadata. Operational Suite code lives under `c11c-suite/`; maintenance and QA implementation code belongs under `tools/` or the appropriate Suite package. `c11c-studio` is no longer part of the project; it is historical reference only.

## Root entries intentionally retained

`project.godot`, `GeneradorMaestro.gd`, `GeneradorMaestro.gd.uid`, `Main.tscn`, `icon.svg`, `icon.svg.import`, `build_factory.py`, `release_gate.py`, `README.md`, `AGENTS.md`, `.editorconfig`, `.gitattributes`, `.gitignore`, `.continue/`, `.githooks/`.

Generated/editor state such as `.godot/` and caches is not source organization material.

## Organization script

Canonical maintenance runner:

`c11c-suite/c11c-maintenance/organize_repository_root.ps1`

Wrapper:

`c11c-suite/c11c-maintenance/organize_repository_root.bat`

The script is **dry-run by default**. Use `-Apply` only after reviewing the planned moves. It is deliberately conservative: ambiguous destination collisions are reported rather than overwritten.

The script moves historical 2.19 candidate/context files, redundant root documentation, overlay metadata and known duplicate maintenance entrypoints while preserving the engine/project entrypoints and current C11-C acceptance root file.

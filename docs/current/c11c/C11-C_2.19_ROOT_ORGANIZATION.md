# C11-C 2.19.12 — Repository Root Organization

The root is reserved for project entrypoints and governance. Current operational documentation belongs in `docs/current/` and `docs/master-prompts/`; historical receipts and repair notes belong in `docs/history/`.

## Retained root entries

The engine/project entrypoints remain untouched: `project.godot`, `GeneradorMaestro.gd`, `Main.tscn`, `icon.svg`, `build_factory.py`, `release_gate.py`, `README.md`, `AGENTS.md`, `.continue/`, `.gitattributes`, `.gitignore`, and other explicitly governed project metadata.

The current C11-C acceptance script remains at the root because it is an intentional top-level release gate.

## Organization script

Canonical:

`c11c-suite/c11c-maintenance/organize_repository_root.ps1`

Wrapper:

`c11c-suite/c11c-maintenance/organize_repository_root.bat`

Dry-run is the default. `-Apply` performs only allowlisted moves. Ambiguous destination collisions are archived rather than overwritten.

The script also quarantines the obsolete misspelled Suite directory `c11c-suite/c11c-maintenace` when the canonical `c11c-suite/c11c-maintenance` exists.

## Freeze requirement

A final freeze is blocked while known root documentation clutter or the obsolete misspelled Suite alias remains active.

## V35.1 safety correction

When a mapped destination already exists with different SHA-256 bytes, the root source is preserved intact under `docs/history/root_conflicts/` with a timestamp. The canonical destination is never overwritten. Dry-run reports `WOULD_ARCHIVE_CONFLICT`; apply reports `ARCHIVED_CONFLICT`.

Only a genuinely unresolved `CONFLICT` remains a failing condition.

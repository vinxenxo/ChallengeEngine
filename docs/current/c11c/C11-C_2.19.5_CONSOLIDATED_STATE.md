**ACTIVE REPAIR CANDIDATE — NOT FROZEN.**

2.19.5 is the consolidated continuity revision of the 2.19 branch. It keeps the worker-local concurrency architecture introduced in 2.19.4 and fixes one test-harness defect discovered during workstation validation.

### Critical distinction

The observed hang when running `C11CParallelReviewWorkerIsolationContractTest.gd` was caused by the contract test itself using `_ready()` as its entrypoint. The test inherits `SceneTree`, which inherits `MainLoop`; command-line MainLoop scripts execute through `_initialize()`. Because the new test never entered `_initialize()`, it never reached its assertions or `quit()`. This does **not** establish a production worker-serialization bug. Godot's MainLoop documentation defines `_initialize()` as the initialization callback for this script model. 

The earlier 2.19.3-v2 global mutex experiment remains superseded. The active batch architecture is genuine worker-local isolation, not serialization.

## Parallel Art Direction architecture

Canonical command:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\prototypes\c11c_bulk\run_c11c_art_direction_batch_v4.ps1 `
  -Workers 7 `
  -All `
  -Reset
```

`Workers=7` is a real concurrency contract. Each loop job is executed inside its own temporary Godot project root. The worker copy excludes generated `artifacts/`, source `.godot/`, `.git/`, caches, source `override.cfg`, and retired `c11c-studio/`. Each worker can therefore own Movie Maker state independently.

The batch uses no project-global mutex. It emits worker slot/root markers and requires `MAX_OBSERVED_CONCURRENCY > 1` whenever more than one loop task is scheduled with more than one worker.

The production architecture has not been changed by the 2.19.5 test fix.

## Test lifecycle rule

Command-line Godot tests implemented as `extends SceneTree` or `extends MainLoop` must enter their test body from `_initialize()` (or intentionally from `_init()` where the test is deliberately written for that lifecycle). They must explicitly terminate with `quit()` or return `true` from a MainLoop process callback.

The 2.19.5 Suite self-test specifically guards `C11CParallelReviewWorkerIsolationContractTest.gd` against reintroducing `_ready()`.

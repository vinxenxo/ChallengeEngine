### V33 PowerShell crosswalk syntax repair

The V32 crosswalk logic was semantically correct but used a `[ordered]` hash literal with an immediate index expression, which PowerShell 5.1 rejects at parse time. V33 keeps the same crosswalk but declares it once as a normal hashtable and resolves `$loopTechnicalIds[$familyKey]` separately. No validation semantics or runtime product code changed.

# C11-C 2.18.0 — GUI + Production Stabilization

## Status
ACTIVE / operational stabilization checkpoint.

## Verified production baseline

The Challenge production wrapper is operational with both:

- `REVIEW_720` → 720×1280
- `MASTER_1080` → 1080×1920

Both use the historical Challenge source capture path at 540×960. Delivery scaling occurs after capture; Challenge mechanics, RNG, `SimulationResult`, `winning_frame`, `close_calls`, `WinningFrameDetector`, `RenderedFrameStream`, C7 and C9 contracts remain outside the change.

## C11-C visual production

Visual Loops and Visual Drills retain their proven C11-C 720×1280 review capture. Central delivery profiles may produce 540×960, 720×1280 or 1080×1920 outputs after that capture.

All current C11-C delivery profiles target 30 FPS, with the broader product standard allowing 24–60 FPS when a future profile explicitly declares another target.

## Visual Drill timing

- Tracking: 3 s PRE_ROLL + 21 s GAME + 3 s END_CTA = 27 s / 810 frames.
- Saccade, Pursuit, Peripheral Scan: 3 s + 17 s + 3 s = 23 s / 690 frames.

The GUI launches the dedicated producer wrapper; it does not own Drill timing.

## Producer GUI 0.9.0

The UI keeps the approved two-column information architecture but removes the temporary banner/header and visible instructional helper copy.

Variation controls are compact visual sliders. Each parameter has an `ALEATORIO` checkbox; random is the default and disabling it enables the slider. Enum parameters also use sliders so the visible control is consistent.

The production queue keeps completed entries instead of deleting them. The currently running row receives a strong selection highlight. Completed entries are visually dimmed. Manually seeded entries whose product already exists are shown as `YA PRODUCIDO` and are not queued unless `FORCE` is enabled.

## Delivery profile authority

`profiles/delivery/c11c_video_delivery_profiles.json` is the only delivery-profile catalog. Alias profiles resolve through `alias_of`. Wrappers do not assume that every profile stores its dimensions directly.

## Loop wrapper fix

`run_c11c_production.ps1` previously attempted to read `profiles.<id>.fps`, but the 2.17 profile schema did not declare an exact target FPS. 2.18 adds explicit `fps=30` to active profiles and makes alias resolution fail-closed.

## Drill wrapper fix

The Drill production wrapper now resolves delivery aliases and explicitly targets 48 kHz stereo AAC at the source-audio mux stage, so `REVIEW_720` is also compliant with the current audio delivery target.

## UX principles

No visible explanatory paragraphs are used in the working area. Validation/errors remain visible only when actionable. Status is kept in the minimal application status bar.

## Next acceptance gate

Run Producer GUI self-test/preflight, then one A LA CARTA Challenge, one A LA CARTA Visual Loop and one A LA CARTA Visual Drill using `MASTER_1080`. After those three runtime passes, the GUI may be treated as the single orchestration surface for the next phase.


## Delivery configuration hardening

Active profiles now declare an exact target FPS, encoder, CRF/preset and GOP frame count. Wrappers resolve aliases before reading dimensions or codec settings.

# D9.15 — Operator GUI Evidence Capture Guide

Status: capture/record workflow only. This guide does not declare acceptance and does not authorize media, renderer, D4.8, freeze or release.

## Required pairings

The recorder derives 13 required surface/capability pairings from `definitions/c11d/d9/D9_15_GUI_OPERATIONAL_ACCEPTANCE_V1.json`: Config/configuration; Producer/production_planning; Test/validation; Catalog/catalog_identity; Producer+Catalog/provenance; Producer+Test+Maintenance/logs; Maintenance/maintenance; Producer+Catalog+Maintenance/reproducibility. Each entry must be based on an actual Windows GUI action and a screenshot or copied visible output.

## Safe evidence path

Save screenshots or copied GUI logs under `artifacts/evidence/d9_15_operator/`. Supported extensions: PNG/JPG, TXT/LOG/JSON. Evidence files must be non-empty; the recorder stores byte count and SHA-256 and rechecks them on every audit. No media/video/audio artefacts should be created.

## Commands

Initialize once (creates only the evidence ledger):

```powershell
python .\tools\c11d\baseline_candidate\operator_evidence.py init
```

For each actual observation, first save the screenshot/log into the approved evidence directory, then append one record. Example:

```powershell
python .\tools\c11d\baseline_candidate\operator_evidence.py record `
  --surface c11c-config `
  --capability configuration `
  --action "Config GUI: contracts/profile view; validate/hash/diff/backup/restore visible" `
  --evidence-file artifacts/evidence/d9_15_operator/config_configuration.png `
  --observed-status PASS `
  --operator "operator" `
  --operator-attestation I_CONFIRM_GUI_OBSERVED_AND_EVIDENCE_VERIFIED_NO_MEDIA
```

Use only capability/surface pairs listed by `python .\tools\c11d\baseline_candidate\operator_evidence.py status`. For BLOCKED or incomplete functionality record `--observed-status BLOCKED`; do not mark a capability PASS to improve candidate eligibility. Optional request/plan/lifecycle hashes should be supplied only when actually visible and copied from the GUI output.

Audit status at any time:

```powershell
python .\tools\c11d\baseline_candidate\operator_evidence.py status
```

Only once the output shows all 13 latest entries PASS and no pending/blocked entries, and after reviewing all evidence, explicitly finalize D9.15 operational acceptance:

```powershell
python .\tools\c11d\baseline_candidate\operator_evidence.py finalize --operator-attestation I_CONFIRM_ALL_D915_PAIRINGS_REVIEWED_NO_MEDIA
```

Finalize writes a sealed checkpoint bound to the ledger and historical C11-C manifest. The checkpoint can close only the D9.15 no-media GUI operational matrix; it cannot grant D4.8, renderer activation, real-media acceptance, D9.16 full acceptance, D9.17 closure, baseline freeze or release authority.

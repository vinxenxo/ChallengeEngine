The GUI delegates operations to the same Python backend as the CLI. No second maintenance engine and no sixth operational suite are introduced.

## Operations

| Operation | Default | Apply gate | Mutation boundary |
|---|---|---|---|
| Maintenance plan | Dry run | None | Read-only inventory/governance report |
| Documentation audit | Dry run | None | Read-only; does not invoke the C11-C documentation consolidator |
| Freeze preflight | Dry run | None | Read-only; never creates a release archive or grants release authority |
| Transient cleanup | Preview | `--apply --confirm CLEAN_TRANSIENTS_ONLY` | Only `artifacts/scratch` and `artifacts/tests/logs/verbose`; files are reversibly archived, not permanently deleted |
| Legacy surface quarantine | Preview | `--apply --confirm QUARANTINE_C11D_CONTROL` | Only `c11c-suite/c11d-control`; archived intact beneath `docs/history/root_conflicts/` |
| Legacy surface restore | Preview | `--apply --confirm RESTORE_C11D_CONTROL` | Restore only from the latest ledger-backed quarantine if the source is absent and tree/manifest hashes match |
| Transient archive restore | Preview | `--apply --confirm RESTORE_CLEANUP_ARCHIVE` | Latest ledger-backed archive only; existing source files are never overwritten |

Every mutation is explicit and allowlisted. Conflicts block the operation; destinations are never overwritten and the code does not merge directories. The append-only ledger records hashes, original paths, quarantine destinations and historic manifest references. A failed ledger commit triggers rollback; if rollback itself fails the backend reports `RECOVERY_REQUIRED` instead of masking the condition.

## Legacy `c11d-control` and manifest reconciliation

The shared launcher must continue to register exactly:

`c11c-test`, `c11c-producer`, `c11c-catalog`, `c11c-config`, `c11c-maintenance`.

`c11c-suite/c11d-control` remains unregistered. The C11-C freeze package manifest currently records four files under that legacy path. D9.11 preserves `release/C11C_FREEZE_PACKAGE_MANIFEST.json` byte-for-byte as historical evidence and records its original SHA-256 and file entries in the append-only ledger. It does not edit or regenerate the C11-C manifest. The physical quarantine action is operator-triggered, is not performed by applying this overlay, and can be reversed only through the validated restore command.

## Protected roots and release boundary

The backend refuses generic paths, path traversal, symlinks/junctions, arbitrary directory moves, changes to protected roots, source overwrites and manifest rewrites. Cleanup uses its declared two-root allowlist only. C11-C immutable reference hashes are checked against the roadmap.

`D4.8=BLOCKED`, `master_seed=NOT_ADOPTED`, automatic seed generation/runtime derivation remain disabled, gameplay/music seeds remain independent, `renderer_activation=false`, `production_execution=false`, `release_authority=NONE`, and frozen C11-C mutation remains forbidden.

Freeze preflight deliberately returns `freeze_ready=false`: it is readiness inspection, not authorization to create a D release or alter the frozen C11-C package.

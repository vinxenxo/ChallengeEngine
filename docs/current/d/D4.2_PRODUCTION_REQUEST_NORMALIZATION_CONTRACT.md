# C11-D D4.2 - Production Request Normalization + Validation

## Status

PASS / CLOSED.

## Objective

D4.2 converts the D4.1 declarative Production Request schema into an executable normalization and validation contract.

## Canonicalization

The normalizer validates the request, applies deterministic defaults and explicit UNKNOWN values, preserves stable field order and computes SHA-256 over the canonical UTF-8 JSON representation.

Interface-origin provenance is not semantic request identity. GUI and CLI normalize `request_origin` to UNKNOWN in the canonical request while the source interface remains represented by the test input/evidence.

`parent_request_id` is also excluded from semantic identity and normalized to UNKNOWN. `request_id` remains in the canonical request for traceability within the production job scope.

## Validation

D4.2 validates:

- schema version;
- REVIEW / PRODUCTION mode;
- Challenge identity against the D4.1 evidence vocabulary;
- delivery profile identity against the D4.1 evidence vocabulary;
- structural seed;
- dedicated music seed;
- duration and variation;
- personalization;
- editorial metadata;
- output intent;
- provenance;
- explicit UNKNOWN/default handling.

The normalizer rejects `winning_frame`, `close_calls`, simulation-result fields and other simulation-derived controls.

## GUI / CLI parity

The D4.2 fixture pair uses semantically identical requests with different interface-origin provenance. Both normalize to byte-identical canonical JSON and the same SHA-256 request identity.

## Seed isolation

`seed` and `music_seed` remain separate required fields. D4.2 does not consume gameplay or structural RNG.

## Runtime boundary

D4.2 activates no GUI, no production CLI, no renderer and no orchestrator. Runtime authority remains NONE.

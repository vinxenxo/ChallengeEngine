# C11-D D4.5 — CLI Adapter Contract

## Status

PASS / CLOSED. Next: D4.6 — GUI Adapter.

## Responsibility

The CLI is a transport and interface adapter. Its path is:

```text
argv -> parse -> load JSON -> D4.2 normalize -> D4.3 resolve personalization
     -> D4.4 build Production Plan -> emit plan/status
```

The adapter imports and calls the existing implementations in:

- `tools/c11d/d4/production_request_normalizer.py`
- `tools/c11d/d4/personalization_resolver.py`
- `tools/c11d/d4/canonical_production_orchestrator.py`

It owns no seed calculation, music generation, personalization rules, delivery-profile rules, simulation, rendering, encoding, GUI logic, or plan identity. The plan and its SHA-256 come from D4.4. The adapter does not add fields to the plan.

## Command line

```powershell
python.exe tools/c11d/d4/production_cli.py --request <request.json>
python.exe tools/c11d/d4/production_cli.py --request <request.json> --output <plan.json>
python.exe tools/c11d/d4/production_cli.py --request <request.json> --print-json
```

`--output` is optional. `--print-json` prints the canonical plan JSON. REVIEW reports `VALIDATED`; PRODUCTION reports `PLANNED`. Neither mode performs physical production. There are no `--render`, `--execute`, `--publish`, or `--encode` options.

## Failure codes

| Code | Meaning | Validation authority |
|---:|---|---|
| 0 | Plan created successfully | D4.4 |
| 1 | Invalid request or request JSON | D4.2 |
| 2 | Unexpected D4.2 normalization failure | D4.2 |
| 3 | Personalization failure | D4.3 |
| 4 | Orchestration / plan construction failure | D4.4 |
| 5 | CLI usage, governance, output, or internal failure | Adapter/runtime |

## Runtime boundary

The REVIEW and PRODUCTION fixtures both traverse the same normalizer, personalization resolver, and orchestrator. PRODUCTION is only a plan mode in D4.5. Renderer activation and production execution remain false; runtime authority is `NONE`.

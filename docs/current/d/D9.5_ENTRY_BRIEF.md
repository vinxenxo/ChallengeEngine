# C11-D D9.5 — Suite Integration / Studio Architecture Adoption

## Entry condition

D9.4 = PASS / CLOSED checkpoint.

## Objective

Convert the accumulated D branch from a CLI-verifiable contract set into one coherent operator experience inside the canonical `c11c-suite`.

The historical Studio specifications are used as **architecture requirements**, not as a second product root. The active implementation remains `c11c-suite`.

## Non-negotiable principles

1. GUI and CLI are co-equal operator surfaces over the same canonical backend.
2. GUI code does not reimplement simulation, RNG, rendering, audio generation or FFmpeg logic.
3. Backend remains the source of truth for configuration, manifests, effective values, provenance and validation.
4. Protected/frozen state remains visually explicit.
5. D4.8 production activation remains governed by its existing policy.
6. D8 release authority remains NONE.
7. D9 physical pilots remain explicitly authorized operations.
8. D10 remains blocked until real GUI acceptance.

`D9.5.0 foundation → D9.5.1 native D4/D6 operator surfaces → D9.5.2 D5/D7/D8/D9 operator surfaces → D9.5.3 operations/reproducibility/logging convergence → D9.5.4 real GUI E2E acceptance → D9.6 final D9 acceptance`

**Scope:** validate the C11-D-only adapter binding preview from canonical request → editorial personalization → plan → bridge record. The adapter is deliberately **PREPARE_ONLY**. This runbook does not authorize the renderer, create production media or close D9.

- Adapter contract: `definitions/c11d/production/C11D_RENDER_ADAPTER_BOUNDARY_D9_10_V1.json` (read-only Config registry key `D9_D_ONLY_RENDER_ADAPTER_BOUNDARY`).

It carries contract/request/editorial/plan/bridge hashes, model-allowlisted editorial bindings, explicit profile and audio values, and separate gameplay/music seed domains. It does not bind simulation truth or derived telemetry. The envelope is an inspectable binding preview and is not accepted as renderer-native input.

Required invariant values include `renderer_dispatch_invoked=false`, `renderer_input_emitted=false`, `renderer_activation=false`, `production_execution=false`, `media_output_created=false`, `output_artifact_path=null`, `D4.8=BLOCKED`, `release_authority=NONE`, and `c11c_source_mutation=false`.

## Focused validation — no screenshots required

Run from the repository root in Windows PowerShell:

```powershell
python .\tools\c11d\d9\test_editorial_render_bridge.py
python .\c11c-suite\c11c-producer\test_producer_gui_contract.py
python .\c11c-suite\c11c-config\test_config_gui_contract.py

python -u .\c11c-suite\self_test.py
```

The report tool runs five focused checks by default (D9.10 bridge/adapter, static Producer GUI contract, Config GUI contract, Config registry self-test and candidate preflight). It writes `D9_10_AUTOMATED_ACCEPTANCE_REPORT.json` and per-check stdout/stderr logs under `artifacts/tests/c11d_d9/d910_adapter_acceptance/<RUN_ID>/`; it needs no screenshots and creates no media. The optional `--include-aggregate` flag also runs `c11c-suite/self_test.py` inside the recorded report, but running the aggregate separately is the default operator flow.

The report pins the historical C11-C manifest hash and emits `operator_gui_runtime_observed=false` unless actual runtime observation was recorded separately. This is deliberate: a static GUI contract test does not claim a Qt window was launched.

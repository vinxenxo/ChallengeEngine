# C11-D D4.3 — Personalization Contract

## Status

PASS / CLOSED. Runtime authority remains NONE.

## Purpose and boundary

D4.3 resolves the declarative `personalization` section of a D4.1 Production Request into a normalized editorial presentation object. It performs JSON validation, normalization, canonical serialization, and SHA-256 hashing only.

The boundary is:

```text
Production Request -> Personalization Resolver -> Normalized Personalization
```

Personalization may affect editorial presentation. It cannot alter Challenge behavior, simulation truth, mechanics, seeds, or delivery execution. The resolver does not import or call Godot, a renderer, simulation, Challenge execution, FFmpeg, the music engine, `WinningFrameDetector`, GUI, CLI production, or an orchestrator.

## Registry

`definitions/c11d/personalization/C11D_PERSONALIZATION_PROFILE_REGISTRY_V1.json` is the declarative profile catalog, version 1.0.

| Profile | Meaning | Allowed targets |
|---|---|---|
| `none_v1` | Neutral; must be disabled and have no values | none |
| `editorial_text_v1` | Editorial presentation text; must be enabled | `title`, `subtitle`, `call_to_action`, `language`, `player_name`, `challenge_label` |

The editorial profile accepts only the explicit allowlist. Unknown envelope keys, value keys, profile IDs, and protected simulation/control fields are rejected. `player_name` and `challenge_label` are the only declared placeholder values. No Challenge-specific personalization profiles are introduced.

## Normalization and identity

- Strings are trimmed.
- `language` is lowercased.
- Missing, null, or empty optional editorial values become `UNKNOWN`.
- Values have deterministic field order and are serialized as compact UTF-8 JSON for SHA-256.
- The resolver extracts only the Production Request's personalization declaration; it does not rewrite or return request seeds.
- A request with unchanged `seed` and `music_seed` retains both values when presentation text changes; the normalized personalization hash changes.
- `none_v1` is selected for absent/UNKNOWN profile identity when personalization is disabled; enabled requests with absent/UNKNOWN profile identity resolve to `editorial_text_v1`.

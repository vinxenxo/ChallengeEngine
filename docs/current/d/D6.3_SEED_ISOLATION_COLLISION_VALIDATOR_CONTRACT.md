# C11-D D6.3 — Seed Isolation + Collision Validator

**Purpose:** read-only governance validation of the D6.1 authorities and D6.2 resolver/derivation behavior. D6.3 adds no authority and does not change runtime behavior.

## Identity, values and collisions

Canonical identity is the governed authority/domain pair. GAMEPLAY (`gameplay.seed`) consumes only the GAMEPLAY `request.seed`; MUSIC (`music.seed`) consumes only MUSIC `request.music_seed`. Cross-domain use fails in both directions.

Equal numeric values across the independent domains are valid: `GAMEPLAY=424242` and `MUSIC=424242` are `VALUE_REUSE`, not an identity collision. Reusing an explicit value within a domain is likewise valid. The collision matrix separately detects duplicate authority, duplicate seed identity, conflicting domain, conflicting owner, multi-domain consumers, ambiguous/ungoverned authorities, unknown/shared-RNG/Producer/master-seed promotion, and protected-surface promotion.

## Request isolation and derivation corpus

The validator exercises the D6.2 resolver with canonical D4.2-normalized requests. Changing gameplay while holding music fixed must preserve the MUSIC resolution; changing music while holding gameplay fixed must preserve GAMEPLAY resolution.

The D6.2 derivation is re-evaluated over a fixed 32-case corpus spanning parent seeds, GAMEPLAY/MUSIC namespaces, and algorithm versions. D6.3 verifies the namespace inputs include algorithm ID, algorithm version, domain, parent seed and canonical UTF-8 encoding. It checks repeatability, domain separation, parent separation and version separation. The report states only that **no collision was observed in this deterministic validation corpus**; it does not claim SHA-256 collision impossibility.

## Governance evidence and compatibility

D6.0 shared RNG remains `OBSERVED_SHARED_RNG_STATE`, not a canonical authority. D6.0 did not prove that one RNG state feeds both canonical domains; D6.3 records the observation and makes no runtime refactor. The six Producer nondeterministic selections remain `NOT_CANONICAL`. All 896 D6.0 unknown findings remain evidence and are not promoted.

`master_seed` remains `NOT_ADOPTED`, including as an authority or active derivation parent. `winning_frame`, `close_calls`, `SimulationResult`, `WinningFrameDetector`, `RenderedFrameStream`, and C7/C9 contracts are protected from seed identity. D3 Music Engine V5 isolation, D4 `seed`/`music_seed` field separation, and the D4.8 production authorization block are rechecked. No physical authorization is inferred.

## Runner and mutation guard

`tools/c11d/d6/run_d6_3_seed_isolation_collision_validator.ps1` supports Windows PowerShell 5.1. It snapshots the repository around two validator runs; only `artifacts/tests/c11d_d6/d6_3/` may differ. It also hashes D6.0 evidence, D6.1 registry/policy, D6.2 receipt/resolver/spec, D3, and D4 protected inputs. The four JSON outputs use deterministic UTF-8 without BOM and contain no timestamps or random vectors.

The validator rechecks the frozen C11-C ZIP, source tree and `build_factory.py` SHA-256 values. Runtime authority is `NONE`; production, renderer, Godot production, and FFmpeg production execution are false.

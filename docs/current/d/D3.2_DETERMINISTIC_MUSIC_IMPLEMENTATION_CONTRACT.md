# C11-D D3.2 - Deterministic Music Implementation / Render Comparison

## Status

PASS / CLOSED.

## Implementation

The shared deterministic procedural music renderer `c11d_music_engine_v5` version 5.0 is implemented as one toolchain component driven by `challenge_8bit_v1`.

## Deterministic comparison

D3.0 found no historical audio files suitable as an authoritative baseline. D3.2 uses a repeat-render plus seed-control comparison.

- same request and same music seed => identical parameter hash;
- same request and same music seed => identical WAV SHA-256;
- different music seed => different WAV SHA-256;
- stable frame count;
- no PCM hard clipping;
- correct engine/style identity.

## Hardening

PowerShell 5.1 variable names are case-insensitive, so V4 uses semantically unique variable names. Temporary renders use `%TEMP%\\c11d32` to avoid Windows MAX_PATH.

## Isolation

Music seed is isolated from gameplay and structural RNG. Synchronization is presentation-timeline-only. No simulation truth, `winning_frame` or `close_calls` mutation occurs. C11-C Visual Loop and Visual Drill paths remain protected.

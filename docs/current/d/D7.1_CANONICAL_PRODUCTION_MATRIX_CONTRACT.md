# C11-D D7.1 — Canonical Production Matrix Contract

## Purpose

D7.1 establishes the canonical production coverage matrix as a declarative governance artifact. It does not activate renderer execution, production rendering, catalog authority, or runtime seed generation.

## Canonical authority

`C11D_PRODUCTION_MATRIX_SPEC_V1.json` defines the matrix authority. D7.1 owns the matrix authority; D4.4 remains owner of the canonical production plan; D6.1 remains owner of seed governance; D6.2 remains owner of seed resolution.

## Core dimensions

The core matrix is the Cartesian product of:

- all repository `CHALLENGE_*.json` challenge definitions;
- all evidence-backed delivery profiles declared by the D4 production-request contract/evidence;
- modes `REVIEW` and `PRODUCTION`.

Current expected coverage is 9 challenges × 5 delivery profiles × 2 modes = 90 core cases.

No concrete seed values are generated by the matrix. It declares only the canonical seed sources:

- GAMEPLAY → `request.seed` → D6.2 `gameplay` authority;
- MUSIC → `request.music_seed` → D6.2 `music` authority.

Numeric seed equality across domains is valid because authority/domain identity is distinct.

## Personalization

The core matrix uses `none_v1`. Personalization is not a seed authority. Existing D4 personalization coverage remains evidence and is not expanded into the core Cartesian product in D7.1.

## Variation

`variation_index` is not a seed authority in D7.1.

## Governance

- cross-domain seed sharing: FORBIDDEN;
- master_seed: NOT_ADOPTED;
- derivation runtime activation: disabled;
- automatic seed generation: forbidden;
- runtime authority: NONE;
- production execution: false;
- renderer execution: false;
- catalog authority: NOT_ESTABLISHED_IN_D7_1.

## Validation

D7.1 must verify complete core coverage, uniqueness of matrix keys, known challenges/profiles/modes, canonical GAMEPLAY/MUSIC seed bindings, and production/runtime fences. Negative tests must prove invalid mappings and activation attempts are rejected.

## Mutation rule

The runner may change only `artifacts/tests/c11d_d7/d7_1/`. The canonical spec and policy are source governance documents and must not be rewritten by the runner.

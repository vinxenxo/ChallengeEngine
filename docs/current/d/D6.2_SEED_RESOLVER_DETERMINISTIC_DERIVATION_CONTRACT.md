# C11-D D6.2 — Seed Resolver / Deterministic Derivation

**Status:** adapter and governance checkpoint; runtime authority remains `NONE`.

## Canonical resolution

D6.2 consumes a canonical Production Request normalized by the existing D4.2 `production_request_normalizer.py`. It calls that normalizer to confirm canonical form and does not introduce another request interpretation.

The resolver maps `request.seed` to authority `gameplay.seed` / domain `GAMEPLAY`, and `request.music_seed` to `music.seed` / domain `MUSIC`. Both are explicit independent inputs. Equal numeric values are valid because authority identity and domain remain distinct. Missing or invalid values are rejected; the resolver never generates a replacement. The six Producer automatic selections remain outside canonical authority and Producer behavior is unchanged.

`master_seed` is `NOT_ADOPTED`; it is not a canonical authority or request field. Shared/global RNG is not an authority. Cross-domain consumption and protected simulation results as seed inputs are rejected.

## Deterministic derivation capability

`C11D_SEED_DERIVATION_SPEC_V1.json` defines a pure SHA-256 capability. Its canonical UTF-8 JSON input includes algorithm ID, algorithm version, uppercase domain, and non-negative integer parent seed. The first eight digest bytes are converted to an unsigned big-endian 64-bit integer. This definition avoids native `hash()`, platform-dependent conversion, global RNG state, time, UUID and entropy.

Derivation vectors exercise same-input repeatability, domain separation, parent separation, and version separation. The function is available for governed future use, while D6.1 policy keeps `derivation_allowed = false`. The active resolver accepts only explicit D4 fields and rejects a derived mode with `DERIVATION_POLICY_DISABLED`. No C11-C runtime internals participate.

## Validation and boundaries

The validator checks the actual D6.1 registry/policy, D4.2 canonical normalizer and schema, D3 Music V5 isolation, D4 seed separation and production authorization fence, D4.8 blocked production, and frozen C11-C ZIP/tree/build identities. Negative cases cover missing/invalid seeds, unknown authority, both cross-domain directions, disabled derivation, nondeterministic sources, shared RNG, Producer auto-selection, master seed, and protected C11-C surfaces. Positive cases prove equal numeric values are accepted and changes in one domain leave the other resolution unchanged.

The Windows PowerShell 5.1 runner snapshots the repository around two runs. Only `artifacts/tests/c11d_d6/d6_2/` may differ. It verifies registry, policy, derivation spec, D3 and D4 inputs remain unchanged and compares all four evidence files and SHA-256 values. JSON evidence is deterministic UTF-8 without BOM and contains no timestamps.

Runtime authority is `NONE`; production, renderer, Godot production, and FFmpeg production execution are false. D4.8 remains production-blocked and no physical authorization is inferred.

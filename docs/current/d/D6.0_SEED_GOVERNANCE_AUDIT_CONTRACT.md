# C11-D D6.0 — Seed Governance Audit Contract

## Purpose and boundary

D6.0 discovers and classifies existing seed and RNG mechanisms before a canonical seed registry is introduced. It is audit-only. It does not assign new seed authority, derive replacement seeds, alter request schemas, or change gameplay, mechanics, RNG behavior, rendering, D3 Music Engine V5, D4 orchestration, or production execution.

The auditor scans source/configuration roots declared in its evidence. Generated media, unrelated repository artifacts, editor caches, and `.git` internals are excluded. Historical test reference files are identified as `HISTORICAL`; test code/configuration is identified as `TEST_FIXTURE`. Matches are evidence records, not errors merely because they contain “random” or “seed”.

## Taxonomy

Domains: `GAMEPLAY`, `MUSIC`, `VISUAL_VARIATION`, `PRESENTATION`, `EDITORIAL`, `DELIVERY`, `UNKNOWN`.

Classifications: `EXPLICIT_SEED`, `DERIVED_SEED`, `RNG_INITIALIZATION`, `RNG_CONSUMPTION`, `NONDETERMINISTIC_SOURCE`, `LEGACY`, `HISTORICAL`, `TEST_FIXTURE`, `UNKNOWN`.

When source evidence does not support a domain, the auditor records `UNKNOWN`; it does not infer a value from a filename or numeric seed equality. Each finding records path, line, symbol/callsite, seed field, supported domain, classification, producer, consumer, derivation, determinism, runtime relevance, runtime authority, and source excerpt.

## Governance observations

The report separately checks module/global RNG state and nondeterministic sources. A module-level random API is not automatically treated as gameplay RNG sharing. Cross-domain engine-state sharing is reported only when evidence supports that conclusion. Automatic seed selection in authoring/production tools is reported as a source distinct from the gameplay engine's random stream.

D4 `request.seed` remains the `GAMEPLAY` domain and `request.music_seed` remains `MUSIC`. D3 Music Engine V5 must consume its dedicated `music_seed` and remain decoupled from structural/gameplay RNG. D4 personalization is not treated as a seed producer unless source evidence demonstrates that behavior. `winning_frame`, `close_calls`, `SimulationResult`, `WinningFrameDetector`, `RenderedFrameStream`, C7 audio contracts, and C9 authoring contracts remain `PROTECTED / NO_SEED_AUTHORITY`.

## Outputs and determinism

The runner requires D5.5 PASS/CLOSED, snapshots the repository worktree before and after, and permits writes only in `artifacts/tests/c11d_d6/d6_0/`. `.git` internals and those D6.0 evidence outputs are excluded from the content snapshot. It does not move, delete, rename, or rewrite source/definition files and does not invoke Godot, FFmpeg, a renderer, or production execution.

Outputs are canonical UTF-8 JSON with stable ordering and no timestamps:

- `d6_0_seed_inventory.json`
- `d6_0_seed_usage_matrix.json`
- `d6_0_governance_findings.json`
- `d6_0_audit_receipt.json`

The builder performs two in-memory audits and compares their canonical JSON. The runner is executed twice to compare all four output SHA-256 hashes. Findings, including `UNKNOWN`, warnings, or blockers, are preserved; they are not normalized away to obtain audit completion.

## PASS gate

D6.0 passes when the scan completed, every captured observation has a path, classification, and supported domain or explicit `UNKNOWN`, D3/D4 seed separation is evidence-backed, the frozen C11-C identity is preserved, the mutation guard passes, and runtime authority remains `NONE` with production execution false. A discovered blocker is reported as a governance finding for resolution in its responsible later checkpoint; the audit does not repair it.

On closure, the next checkpoint is **D6.1 — Canonical Seed Registry + Governance Policy**. D6.0 does not create that registry.

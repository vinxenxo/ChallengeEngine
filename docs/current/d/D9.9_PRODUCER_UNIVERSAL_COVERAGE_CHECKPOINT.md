# C11-D D9.9 — Producer Universal Editorial Coverage Checkpoint

**Status: PASS for canonical universal selector resolution and plan-only GUI/CLI adapter parity. D9 remains OPEN. D10 remains BLOCKED.**

## Scope accepted

Producer **0.11.0** extends the existing `c11c-producer` application with a third tab, `C11-D · EDITORIAL UNIVERSAL (D9.9)`. This is not a sixth Suite surface. The form exposes content type, family/type, grammar/subtype or variant/tier, mode, independent gameplay/music seeds, delivery/presentation profiles, variation/audio, scoped editorial inheritance/override, canonical request, resolved editorial payload, universal plan and GUI↔CLI parity evidence. Longform is visible but disabled.

The GUI calls `tools/c11d/d9/universal_producer.py` directly for the canonical resolution, serializes a request, invokes `tools/c11d/d9/universal_producer_cli.py` as a separate process, and compares canonical request, request hash, editorial hash, plan and plan hash. No request/plan logic is duplicated in the GUI.

- Visual Drill: **4 types / 20 tier variants**, also declarative editorial-intent plans only.
- GUI/CLI canonical parity: **3/3** actual separate-process cases, one per currently supported content type; all **61 live selectors** were resolved through the same canonical adapter.
- Negative contract controls: **20/20**. Includes unsupported Longform, selector spoofing, missing/boolean seeds, non-editorial fields, telemetry/simulation truth, invalid provenance, non-canonical delivery, oversized editorial text and unknown request keys.
- Seed contracts: gameplay seed remains `request.seed`; music seed remains `request.music_seed`; editorial text changes alter editorial/plan identity without changing either seed. GUI/CLI provenance is normalized out of semantic identity.
- Existing D9.8 model tests: **25/25** negative cases. Producer 0.10 D4 integration test remains in place.

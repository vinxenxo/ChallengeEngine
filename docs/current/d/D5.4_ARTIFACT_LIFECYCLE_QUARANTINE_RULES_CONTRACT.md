# D5.4 — Artifact Lifecycle / Quarantine Rules Contract

## Status

Checkpoint: **D5.4**  
Mode: **GOVERNANCE_ONLY**  
Runtime authority: **NONE**  
Production execution: **false**  
Filesystem mutation: **false**

## Objective

D5.4 formalizes lifecycle and quarantine governance for the artifact topology established by D5.0–D5.3. It defines admissible state transitions and hard blocks without changing any artifact, manifest, lineage record, or frozen C11-C source.

## Inputs

- D5.0 topology audit evidence.
- D5.1 canonical artifact manifest.
- D5.2 provenance lineage registry.
- D5.3 topology validation evidence.
- Existing D3/D4 evidence where required to preserve lineage and authorization semantics.
- `definitions/c11d/artifacts/C11D_ARTIFACT_LIFECYCLE_POLICY_V1.json`.

## Protected inventory

The current governed topology is expected to contain:

- 75 logical artifact identities.
- 79 physical artifact locations.
- 11 lineage edges.
- 9 governed `ORPHANED` nodes.
- 12,304 global unmanaged candidate observations outside the lineage graph.
- D4.8 authorization state remains `BLOCKED`.

The 12,304 global candidates are **not** promoted, moved, deleted, or inserted into the lineage graph by D5.4.

## Lifecycle states

### ACTIVE
Governed, attributable and eligible for normal downstream use, subject to the separate production-activation policy.

### ORPHANED
A governed identity intentionally retained for governance even though it is not currently part of an active governed topology. It is not production-eligible.

### CANDIDATE_GLOBAL
An unmanaged filesystem observation outside the governed manifest/lineage graph. Discoverability alone never creates governance authority.

### QUARANTINED
An explicitly isolated governance state. The physical artifact remains present and traceable. D5.4 never performs quarantine physically.

### RETIRED
An explicitly retired governance state. Retirement does not authorize deletion.

## Transition rules

Any transition requires an explicit governance decision; no transition is automatic.

- `ACTIVE -> QUARANTINED`: allowed only after identity validation and dependency review.
- `ORPHANED -> QUARANTINED`: allowed only after identity validation and dependency review.
- `CANDIDATE_GLOBAL -> ACTIVE`: requires explicit promotion, a governed manifest identity, a recorded physical hash, evidence-backed provenance and validated lineage. Presence alone is insufficient.
- `QUARANTINED -> ACTIVE`: requires explicit restoration plus revalidation of identity, evidence and lineage.
- `QUARANTINED -> RETIRED`: requires explicit retirement and preservation of the governance record.

No D5.4 path authorizes automatic cleanup, physical move, physical deletion, or production activation.

## Required protections

1. Frozen C11-C identity remains unchanged.
2. D4.8 `BLOCKED` remains `BLOCKED`; no physical authorization may be invented.
3. D3 raw render and delivery master remain distinct artifacts with validated derivation.
4. Duplicate physical copies continue to collapse to their existing logical identity.
5. Existing `ORPHANED` nodes remain records, not deletion candidates.
6. Global unmanaged candidates remain outside the lineage graph.
7. Running D5.4 twice with unchanged inputs produces the same canonical result and hashes.
8. The runner must not modify repository files other than creating its own D5.4 evidence outputs.

## Negative controls

The validator must detect and reject these synthetic governance violations:

- automatic promotion of a global candidate;
- quarantine without explicit decision;
- restoration without revalidation;
- retirement interpreted as deletion authorization;
- production eligibility assigned to a non-active state;
- authorization inferred from D4.8 `BLOCKED` evidence;
- mutation of frozen C11-C identity;
- mutation of the manifest/lineage input during evaluation.

## Pass criteria

D5.4 is `PASS / CLOSED` only when:

- D5.0–D5.3 evidence is present and internally consistent;
- protected inventory counts match 75 identities / 79 locations / 11 edges / 9 ORPHANED;
- 12,304 global candidates remain outside the graph;
- all actual transition rules and hard blocks pass deterministic negative tests;
- no manifest, lineage or frozen C11-C content is changed by the validator;
- repeated evaluation is byte-for-byte deterministic;
- `runtime_authority = NONE`;
- `production_execution = false`;
- `filesystem_mutation = false`.

# C11-D D9.5.0 — Suite Integration Foundation Contract

## Purpose

Introduce the first integrated C11-D operator surface while preserving the existing Suite applications and all frozen backend boundaries.

## Requirements

- active root remains `c11c-suite`;
- no parallel operator root is created;
- D4–D9 status is discoverable from canonical receipts;
- canonical D runners can be launched from GUI;
- sensitive operations require explicit GUI confirmation;
- D4.8 status remains visible as BLOCKED;
- `release_authority=NONE` remains visible;
- D10 gate remains visibly blocked;
- Test, Producer, Catalog, Maintenance and Config remain accessible;
- no C11-C backend modification is permitted;
- no renderer implementation enters the GUI;
- GUI remains asynchronous and must not block while a runner is executing.

## Acceptance for D9.5.0

Static acceptance requires Python compilation and command-target existence. Real Windows GUI acceptance is intentionally deferred to D9.5.4 so that the user can exercise the UI on the real workstation.

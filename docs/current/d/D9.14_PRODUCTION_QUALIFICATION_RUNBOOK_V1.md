# D9.14 — Bounded Production Qualification Runbook V1

**Purpose:** create and verify real production MP4s using the existing, proven C11-C production launchers so that the Windows/Godot/FFmpeg execution path is exercised and pinned to an identifiable qualification run.

**This is not D9.14 closure, not the final C11-D release baseline, and not release authorization.** The current D9.10 bridge remains planning-only; this qualification does not certify that editorial values entered through the C11-D Producer GUI are bound to rendered pixels. D9.14's ten-case GUI certification, D9.16 full acceptance and D9.17 closure remain separate obligations.

## Scope and safeguards

The run requires the explicit token `RUN_C11D_PRODUCTION_QUALIFICATION_NO_RELEASE`. It executes only three bounded product classes through existing launchers:

1. `CHALLENGE_001` via `run_c11c_challenge_production.ps1`, `REVIEW_720`.
2. Geometric Waves `harmonic_membrane`, two renders with the same gameplay seed and separate audio seeds.
3. Visual Drill `tracking`, with a gameplay seed separate from its music seed.

Outputs go to a new, unique `artifacts/production/c11d_qualification/<run-id>/` folder. An existing run folder is never overwritten. The runner checks H.264/YUV420P/720x1280 output, usable frame count and duration, stereo audio, exact decoded loop-frame replay for the same gameplay seed, differing WAV hashes for two different music seeds, and the C11-C manifest plus source-tree hash before and after execution. It stores each final MP4's SHA-256, stream metadata, launcher logs, a sealed report and a sealed qualification-baseline manifest.

The script never changes C11-C source or its frozen manifest, never updates the canonical D9.14 gate to PASS, and never grants global D4.8 authorization, general D-renderer activation, final baseline freeze or release authority. Qualification media are validation artifacts, not publishable releases.

## Prerequisites

- Run from the repository root in Windows PowerShell 5.1 or newer.
- `python`, `godot.exe`/`godot`, `ffmpeg` and `ffprobe` must resolve on `PATH`.
- Repository C11-C manifest must match `e405d08e4d166b1ad95953558f4a088e73eea9527e6e89244beb4096eac4b953`.
- The D9.15 candidate-only waiver and reconciled D9.11 legacy quarantine must already be present.
- Ensure sufficient disk space. Never run this against a publish/release folder; the script only writes under the bounded qualification root.

## Run

From `C:\Users\vinxe\Projects\ChallengeEngineV01_STATELESS`:

```powershell
python .\tools\c11d\d9\test_production_qualification_contract.py
python .\c11c-suite\c11c-test\test_powershell_parse.py
python .\tools\c11d\baseline_candidate\test_d_baseline_candidate.py

.\tools\c11d\d9\run_d9_14_production_qualification.ps1 `
  -ConfirmProductionQualification RUN_C11D_PRODUCTION_QUALIFICATION_NO_RELEASE
```

The run defaults to separate gameplay seeds `42001`, `42002`, `42003` and music seeds `73021`, `73022`; these can be explicitly overridden. The two music seeds must differ. A unique UTC run ID is created by default. The runner fails closed on missing tools, manifest drift, failed launchers, bad streams, non-deterministic same-seed loop frames, identical changed-seed audio, media hash failure, or a changed source-tree hash.

## Expected result

On a successful run, the terminal reports `C11-D PRODUCTION QUALIFICATION BASELINE SEALED` and the output root contains:

- `media/` — four MP4 outputs (Challenge, two audiovisual loop variants, Visual Drill).
- `D9_14_PRODUCTION_QUALIFICATION_REPORT.json` — sealed report with output and source hashes.
- `C11D_PRODUCTION_QUALIFICATION_BASELINE_V1.json` — sealed identity for the **qualification baseline only**.
- Launcher and source-tree pre/post logs.

The expected status is `BOUNDED_PRODUCTION_QUALIFICATION_PASS_NOT_D9_14_CLOSURE`. It intentionally states `c11d_editorial_renderer_binding=NOT_CERTIFIED_BY_THIS_RUN`, D9.14 not closed, D9.16 blocked, D9.17 blocked, global D renderer OFF and `release_authority=NONE`.

## After the run

Review the MP4s, then run:

```powershell
python .\tools\c11d\d9\production_qualification_contract.py audit `
  --report ".\artifacts\production\c11d_qualification\<RUN_ID>\D9_14_PRODUCTION_QUALIFICATION_REPORT.json" `
  --project-root "."
python .\tools\c11d\baseline_candidate\test_d_baseline_candidate.py
python -u .\c11c-suite\self_test.py
```

The new qualification baseline is a pinned, reproducible production-smoke baseline. It is **not** a substitute for implementing/binding the C11-D editorial renderer or completing the ten D9.14 GUI cases, full evidence review and D9.17 adjudication. Only after those pass may a separate approval create the final C11-D frozen baseline and authorize release.

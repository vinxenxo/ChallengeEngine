## Confirmed exception and root cause

The exact exception captured by both runtime runs was:

```text
RuntimeError: Qt GUI callback raised a modal warning for challenges: C11-D Editorial Universal: Persisted GUI/CLI parity receipt is not a complete PASS
```

The traceback points to `tools/c11d/d9/test_d910_gui_runtime_acceptance.py:128`, where the harness correctly treats a modal warning from the GUI callback as a failed test. The warning is raised in `c11c-suite/c11c-producer/main.py` when `_run_d9_universal_plan()` asks `tools/c11d/d9/cross_suite_lifecycle.py` to build a lifecycle receipt.

This is a deterministic persisted-receipt schema mismatch, not a Qt font or `propagateSizeHints()` problem:

- The current Producer GUI persists seven required parity checks in `gui_cli_parity.json`, including `d_only_adapter_envelope_equal`.
- The lifecycle validator required an exact set of only six keys and therefore rejected the current GUI receipt even if all seven values were true.
- Rejection occurs before the lifecycle receipt is created and correctly surfaces as a modal warning; consequently the GUI runtime harness recorded zero accepted content types.

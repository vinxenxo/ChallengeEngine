# C11-D D6.1 — Canonical Seed Registry + Governance Policy

**Status:** D6.1 implementation contract; runtime activation is `NONE`.

## Purpose and boundary

D6.0 is the complete evidence inventory. The D6.1 registry is intentionally narrower: it records only evidence-backed, owned authorities. It does not copy observations, resolve the 896 unknown findings, modify runtime behavior, or replace D4 request fields. No seed resolver or derivation is activated here.

The canonical authorities are `gameplay` (`GAMEPLAY`, `request.seed`) and `music` (`MUSIC`, `request.music_seed`). Their owners, domains, consumer scopes, determinism, status, derivation metadata and evidence are defined in `definitions/c11d/seeds/C11D_SEED_REGISTRY_V1.json`. Current derivation is `NONE`; future derivation is disabled pending D6.2.

## Evidence semantics

`CANONICAL_AUTHORITY` is governed identity. `OBSERVED_SEED` is evidence only. `DERIVED_SEED` requires an explicit deterministic derivation contract. `LEGACY`, `HISTORICAL` and `TEST_FIXTURE` remain evidence and do not gain runtime authority. `UNKNOWN` remains unresolved evidence. D6.0 counts, including 896 unknown findings, are carried forward without rewriting their classifications.

The governance policy forbids implicit authority, cross-domain sharing, undocumented derivation, nondeterministic canonical authority and global/shared RNG promotion. Shared RNG is recorded as `OBSERVED_SHARED_RNG_STATE`; six Producer nondeterministic selections and two warnings are governance findings only. Neither is repaired by D6.1.

## Validation and evidence

`tools/c11d/d6/seed_registry_validator.py` validates the registry/policy, checks D4 field separation and D3 music isolation, checks the frozen C11-C ZIP/tree/build identity, exercises required negative cases, and writes deterministic UTF-8 without BOM evidence only under `artifacts/tests/c11d_d6/d6_1/`. Registry and policy are authoring inputs and are never rewritten by the runner.

`tools/c11d/d6/run_d6_1_seed_registry_validator.ps1` is compatible with Windows PowerShell 5.1. It snapshots the repository around two validator executions, confirms only the D6.1 evidence directory differs, and compares all four evidence files byte-for-byte and by SHA-256.

The evidence set records registry validation, governance matrix, negative tests and a receipt. Runtime authority remains `NONE`; production, renderer, Godot production and FFmpeg production execution remain false. Protected C11-C surfaces include `winning_frame`, `close_calls`, `SimulationResult`, `WinningFrameDetector`, `RenderedFrameStream`, C7/C9 contracts and frozen source identity.

## Gate and next checkpoint

PASS requires exactly the two evidence-backed authorities above, D4/D3 isolation PASS, governance and negative tests PASS, unknown/legacy/historical/test evidence preserved, shared RNG and Producer selections not promoted, deterministic/idempotent evidence, frozen identity preserved and no non-evidence mutation.

On PASS: **D6.1 = PASS / CLOSED**. **NEXT = D6.2 — Seed Resolver / Deterministic Derivation.** D6.2 decides whether a master seed is justified; D6.1 makes no such decision.

# D9.13 — Cross-Suite Lifecycle Checkpoint

**State:** IMPLEMENTED — backend/static acceptance candidate; Windows operator acceptance pending.

## Objective

Prove that a single canonical plan-only request retains the same identity, seeds, editorial hash, plan hash, bridge hash, profile bindings, and provenance across the existing `c11c-config`, `c11c-producer`, `c11c-test`, `c11c-catalog`, and `c11c-maintenance` surfaces. No sixth operational surface is introduced.

## Canonical output

`tools/c11d/d9/cross_suite_lifecycle.py` builds and verifies a SHA-256 sealed `cross_suite_lifecycle_receipt.json` under the existing Producer evidence directory `artifacts/tests/c11d_d9/producer_universal/<request_id>/`. Catalog reads this receipt as a non-authoritative `CROSS_SUITE_LIFECYCLE_INTENT` projection, Test checks the route/manifest/negative contracts, Config binds read-only canonical registries, and Maintenance independently audits current policy and the historical C11-C manifest.

## Governing invariants

- Same `lifecycle_id`, `identity_sha256`, and `binding_sha256` across all five stages, in exact canonical order.
- Gameplay seed source remains `canonical_request.seed`; music seed source remains `canonical_request.music_seed`; cross-domain sharing, automatic seed generation, and runtime derivation remain forbidden.
- `renderer_activation=false`, `renderer_input_emitted=false`, `production_execution=false`, `media_created=false`, `D4.8=BLOCKED`, `runtime_authority=NONE`, and `release_authority=NONE`.
- Longform remains disabled. The record is plan/provenance intent, not media QA or release evidence.
- Historical `release/C11C_FREEZE_PACKAGE_MANIFEST.json` is read-only and must remain byte-for-byte unchanged.
- Only the five canonical Suite surfaces are operational.

## Negative coverage

The D9.13 tests exercise checksum tampering, stage reordering, cross-stage identity drift, seed/profile drift, forbidden media/release claims, unsafe evidence paths, unsupported Longform, current-contract drift, invalid catalog projection and Maintenance audit failure.

## Exit criteria

Automated contract checks, all three supported content types, canonical GUI/CLI evidence validation, receipt validation, Catalog projection and Maintenance read-only audit must pass. Operator confirms the Producer lifecycle tab and Catalog/Maintenance visibility in Windows. D9.13 does not activate a renderer, create media, authorize production, or close D9.

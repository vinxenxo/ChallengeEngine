# C11-D D8.0 — Boundary / Media Inventory Contract

## Status

D8.0 = INVENTORY + GOVERNANCE ONLY. No media production is authorized.

## Authority

D7 remains frozen and authoritative only for the declarative production-intent chain:

- Matrix: `CANONICAL_D7_1`
- Catalog: `CANONICAL_D7_3`
- Identity/Provenance: `CANONICAL_D7_4`
- Full Acceptance: `CANONICAL_D7_5`

D7 does not authorize physical rendering, encoding, muxing, release staging, publication, or distribution.

## Governance locks

- `master_seed = NOT_ADOPTED`
- gameplay seed authority = `request.seed`
- music seed authority = `request.music_seed`
- cross-domain seed sharing = `FORBIDDEN`
- runtime seed derivation = disabled
- automatic seed generation = disabled
- D4.8 = `BLOCKED`
- runtime authority = `NONE`
- production execution = `false`
- renderer execution = `false`

## Protected C11-C surface

D8.0 must not modify C11-C simulation/mechanics/RNG, `SimulationResult`, `winning_frame`, `close_calls`, `WinningFrameDetector`, `RenderedFrameStream`, C7/C9 contracts, logical 540x960 geometry, or proven C11-C presentation/production behaviour.

## D8.0 permitted actions

D8.0 may:

- enumerate files/directories;
- inspect text/configuration/manifests/receipts;
- discover `ffmpeg` and `ffprobe` and read their `-version` output;
- stat files and compute hashes for governance/evidence files and release-tree files;
- stat media files without opening them for decoding or transformation;
- classify existing tooling and evidence;
- write deterministic D8.0 evidence only under `artifacts/tests/c11d_d8/d8_0/`.

## D8.0 forbidden actions

D8.0 must not:

- render, encode, transcode, mux, decode, extract frames, or loudness-process media;
- invoke FFmpeg/FFprobe against a media file;
- modify, copy, move, delete, quarantine, rename, or normalize media;
- create or alter a release product;
- activate production or renderer execution;
- change D7 authority/evidence or C11-C source/contract content;
- introduce runtime or automatic seed derivation.

## Physical vs logical authority

A path, filename, media file, sidecar, manifest, or historical report does not by itself establish challenge identity, seed authority, provenance, authorization, or release eligibility.

D8.0 records facts and evidence. It does not promote historical evidence or legacy tooling to canonical D8 authority.

## Lifecycle classification

Every release/media-related item discovered by D8.0 must be classifiable as one of:

- `CANONICAL_D8_CANDIDATE`
- `REUSABLE_LEGACY_TOOLING`
- `HISTORICAL_EVIDENCE`
- `NON_AUTHORITATIVE`
- `UNTRUSTED`
- `OUT_OF_SCOPE`

## D7-to-media principle

The D7 catalog is metadata/production intent only. A future D8.4 eligibility decision requires an evidence-backed relation from canonical D7 identity to actual physical media bytes and their provenance. D8.0 records whether the required chain is present; it does not declare media eligible.

## Evidence boundary

D8.0 evidence is allowed only beneath:

`artifacts/tests/c11d_d8/d8_0/`

The D8.0 runner must prove that no file outside this boundary changed during execution.

## Determinism

Evidence is canonical UTF-8 JSON/text with sorted object keys, stable ordering, and no wall-clock timestamps. Repeated execution over an unchanged workspace must produce byte-identical evidence.

## Exit gate

D8.0 may close PASS only when inventory, tooling classification, actual-media presence/absence, FFmpeg/FFprobe availability, provenance path assessment, explicit production/release disablement, and mutation guard all pass.

D8.1 is blocked until D8.0 = PASS/CLOSED.

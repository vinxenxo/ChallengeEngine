# C11-D D7.4 — Catalog Identity / Provenance Contract

## Objective

D7.4 validates the D7.3 canonical catalog without changing the catalog source file, frozen C11-C behavior, simulation semantics, or production execution state.

## Canonical identity

Each catalog item must satisfy:

- `catalog_key == matrix_key`.
- `catalog_item_id == "cat_" + first 16 lowercase hex characters of SHA-256(catalog_key UTF-8)`.
- `identity_hash == SHA-256(canonical catalog item excluding identity_hash)` using UTF-8, sorted keys, compact JSON separators, and a trailing newline.
- Identity values must recompute exactly and remain stable across repeated runs.

## Provenance chain

The validation chain is:

`D7.1 canonical production matrix → D7.2 coverage validation → D6.1 seed registry → D6.2 explicit seed resolver → D6.4 request/plan/provenance integration → D4.4 canonical production orchestrator plan owner`.

D7.4 verifies that referenced provenance paths exist, source SHA-256 values recorded by D7.3 remain current, and the plan owner is `canonical_production_orchestrator`.

## Governance gates

`master_seed=NOT_ADOPTED`, derivation runtime activation is false, cross-domain seed sharing is forbidden, automatic seed generation is false, runtime authority is `NONE`, production execution is false, renderer execution is false, and `D4.8=BLOCKED`.

The catalog remains metadata/intent only. D7.4 does not render media and does not authorize production.

## Mutation scope

Only `artifacts/tests/c11d_d7/d7_4/` evidence may change during the runner.

Expected evidence files:

1. `d7_4_identity_validation.json`
2. `d7_4_provenance_validation.json`
3. `d7_4_negative_tests.json`
4. `d7_4_identity_receipt.json`

## Closure gate

D7.4 closes only when identity validation, provenance validation, negative tests, mutation guard, and deterministic repeated evidence hashes all pass.

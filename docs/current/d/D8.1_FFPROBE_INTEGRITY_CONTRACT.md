# C11-D D8.1 — FFprobe / Media Integrity Contract

## State

D8.0 = PASS / CLOSED. D8.1 is the first physical-media integrity checkpoint.

D8.1 is **read-only media inspection**. It may invoke `ffprobe` against existing media, but it must not render, encode, transcode, mux, extract, normalize, rewrite, move, copy, rename, delete, quarantine, or otherwise modify media or release products.

D7 authorities remain unchanged and are consulted only as metadata/provenance context. They do not authorize release execution.

Protected C11-C boundary remains unchanged: simulation/mechanics/RNG, `SimulationResult`, `winning_frame`, `close_calls`, `WinningFrameDetector`, `RenderedFrameStream`, C7/C9 contracts, logical 540×960 geometry, and proven C11-C presentation/production behaviour.

- music seed = `request.music_seed`
- cross-domain seed sharing = `FORBIDDEN`
- runtime derivation disabled

## Inputs

Primary discovery input is the PASS/CLOSED D8.0 inventory:

`artifacts/tests/c11d_d8/d8_0/d8_0_inventory.json`

D8.1 independently re-enumerates current media beneath `artifacts/` and `release/` and compares the aggregate workspace media count/bytes recorded by D8.0. Any drift blocks D8.1 rather than silently probing a changed corpus.

The frozen D7.5 ZIP may be recorded as baseline metadata, but it is not extracted, rewritten, or used as release authorization.

## Probe scope

Probe-eligible extensions:

`.mp4`, `.mov`, `.mkv`, `.webm`, `.avi`, `.wmv`, `.mxf`, `.gif`, `.wav`, `.mp3`, `.m4a`, `.aac`, `.flac`, `.ogg`, `.opus`, `.aiff`

Known media extensions which cannot be safely interpreted without external raw-format metadata, such as standalone `.pcm` or ambiguous `.alac`, are recorded as `NOT_GENERICALLY_PROBEABLE` and deferred to later checkpoint-specific handling. Their existence alone does not create release eligibility.

## FFprobe integrity test

For every probe-eligible media file:

1. confirm the file exists and is a regular file;
2. invoke the discovered `ffprobe` binary in read-only mode;
3. request JSON container and stream inspection (`format`, `streams`, `programs`, `chapters`, and `error`);
4. require exit code `0`;
5. require parseable JSON;
6. require a non-empty `format` object;
7. require at least one stream;
8. reject explicit `error` output or malformed probe data;
9. record deterministic technical facts without assigning release eligibility;
10. confirm file size and modification timestamp did not change during the probe.

D8.1 does **not** decide visual quality, audio quality/loudness, provenance eligibility, catalog identity, release readiness, or publication status. Those belong to D8.2–D8.7.

## Tool provenance

Record:

- resolved `ffprobe` executable path;
- command type/source;
- `ffprobe -version` output;
- SHA-256 of the executable when it is a regular local file;
- operating-system/runtime context sufficient to reproduce the inspection.

No FFmpeg invocation is permitted by the D8.1 runner.

## Status rules

`PASS` only when:

- D8.0 inventory is present and internally usable;
- current aggregate media count and bytes match the D8.0 inventory;
- `ffprobe` is available;
- every probe-eligible media file passes the integrity test;
- no probe candidate changes during inspection;
- mutation guard passes.

`PASS_NO_MEDIA` is allowed only when the current workspace has zero probe-eligible media and `ffprobe` is available; it is evidence that the integrity mechanism itself passed, not proof that release media exist.

`BLOCKED` when D8.0 inventory is missing/unusable, inventory drift exists, `ffprobe` is unavailable, or any unexpected infrastructure condition prevents trustworthy inspection.

`FAIL` when a discovered probe-eligible media file is unreadable, malformed, changes during probe, or fails the defined integrity requirements.

D8.1 PASS does not authorize production or release.

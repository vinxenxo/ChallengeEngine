# D5.0 — Artifact Topology / Provenance Audit Contract

## State

Audit-only checkpoint. The audit may read repository files and write its own audit, inventory, and receipt JSON. It must not move, rename, or delete repository artifacts, activate a renderer, or execute production. `runtime_authority` is `NONE` and `production_execution` is `false`.

## Purpose

D5.0 establishes a verifiable inventory of physical locations, logical artifact identity, provenance evidence, route class, and lifecycle. A path is location only: filename or directory name alone must never establish Challenge, seed, music seed, request, plan, authorization, or artifact provenance. Unknown facts remain `UNKNOWN` or missing.

The intended lineage is:

```text
Production Request → Production Plan → Authorization → Artifact
```

D5.0 reports links only when evidence supports them. Raw deterministic D3.2 media and the D3.3 delivery master are distinct artifacts connected by their evidence; delivery mastering does not replace the raw render.

## Taxonomy

`REQUEST`, `PLAN`, `AUTHORIZATION`, `MEDIA`, `MANIFEST`, `PROVENANCE`, `VALIDATION_RECEIPT`, `EVIDENCE`, `REPORT`, `SNAPSHOT`, `LOG`, `TEMPORARY`.

Lifecycle states are `ACTIVE`, `HISTORICAL`, `TEMPORARY`, `QUARANTINED`, and `ORPHANED`. `QUARANTINED` means an artifact exists but its provenance is incomplete or invalid; it is neither active nor historical. This checkpoint does not define `PUBLISHED`, `UPLOADED`, or `DISTRIBUTED`.

## Topology scope

- Active inspection roots: `artifacts/`, `definitions/`, `tools/`, and `docs/current/d/`. The audit distinguishes definitions/configuration, tooling, test/review evidence, and production media; their presence under an inspected root does not by itself authorize production use.
- Historical: `docs/history/` and other paths explicitly marked history, historical, or archive.
- Temporary: paths with explicit `tmp`, `temp`, `cache`, `scratch`, or `worker` components.
- Quarantine: paths explicitly under a quarantine component.

No relocation is performed. An explicit declared lifecycle state that contradicts the physical historical/active route produces `TOPOLOGY_CONFLICT` for review.

## Provenance inventory target

The audit inventories current presence and receipt-supported derivability for: `artifact_id`, `artifact_type`, `artifact_version`, `artifact_sha256`, `lifecycle_state`, `request_sha256`, `plan_sha256`, `authorization_sha256`, `challenge_id`, `challenge_version`, `seed`, `music_seed`, delivery profile ID/version, personalization profile ID/version, music engine ID/version, style profile ID/version, `source_revision`, `created_by_component`, `parent_artifact_ids`, `mode`, and `runtime_authority`. Content hashes are calculated for structured JSON evidence and D3/D4 media. Other large legacy media is inventoried with its relative location and byte size; D5.0 does not rehash the full C11-C media corpus.

Artifact identity must be deterministic, for example SHA-256 over canonical identity inputs. D5.0 proposes an identity method and records content hashes; it does not replace existing artifact identifiers. Physical path is recorded separately from logical type and identity.

## Receipts and gate

The audit discovers `d*_validation_receipt.json` beneath `artifacts/tests/c11d_d*` and records checkpoint, result, status, next, and runtime authority. It inspects D3 and D4 evidence without rerunning their production flows. Synthetic route-conflict and provenance-orphan cases are evaluated in memory and do not create repository files.

D5.0 may report `PASS` / `CLOSED` only when D4.9 is `PASS` / `CLOSED`, topology conflicts are zero, unclassified active artifacts are zero, request→plan and plan→authorization links are evidenced, the frozen C11-C archive SHA-256 matches `D85425CF18C5211C8497574F4FC66202D613EACC0EC14CD4E2FEF0B24F634A32`, runtime authority is `NONE`, and production execution is false. Otherwise it reports `BLOCKED` with findings; it must not conceal conflicts or incomplete evidence.

## Outputs and next checkpoint

`artifacts/tests/c11d_d5/d5_0/` contains the topology audit, provenance field inventory, and validation receipt. The D5.0 launcher is idempotent and does not mutate audited source artifacts. After a passing close, the next checkpoint is **D5.1 — Canonical Artifact Manifest**.

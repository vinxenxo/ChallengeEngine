# C11-D D7.3 — Canonical Catalog Builder Contract

## Status

D7.3 is a canonical catalog construction checkpoint. It consumes the closed D7.1 matrix and D7.2 coverage validation and produces deterministic catalog metadata. It does not render media and does not activate production execution.

## Authority

- Matrix authority: `CANONICAL_D7_1`
- Catalog authority introduced by D7.3: `CANONICAL_D7_3`
- Runtime authority: `NONE`
- Production execution: `false`

## Source chain

`D7.1 canonical matrix -> D7.2 coverage validation -> D7.3 catalog`

D6.5, D6.4, D6.2 and D6.1 are consumed as supporting provenance/evidence and must remain `PASS/CLOSED` where their receipts are required.

## Coverage

The current canonical matrix contains 9 Challenges x 5 delivery profiles x 2 modes = 90 core rows. D7.3 creates exactly one catalog item per matrix row.

## Catalog identity

`catalog_key = matrix_key`.

`catalog_item_id` is a stable deterministic identifier derived from SHA-256 of `catalog_key`.

The catalog item also carries an `identity_hash` over canonical item content excluding the identity hash field itself.

## Seeds

Catalog entries reference, but do not generate, the existing governed authorities:

- `request.seed -> gameplay -> GAMEPLAY`
- `request.music_seed -> music -> MUSIC`

`master_seed = NOT_ADOPTED` and derivation runtime activation remains disabled.

## Execution fence

The catalog describes production intent. It is not proof that media exists.

- `production_execution = false`
- `renderer_execution = false`
- `media_rendered_by_catalog = false`
- `runtime_authority = NONE`

D4.8 remains blocked and no authorization is inferred or materialized.

## Provenance

Each catalog item must identify the source matrix key and matrix identity, D7.2 validation, D6.1 seed registry, D6.2 resolver, D6.4 integration evidence, and the D4.4 plan owner.

## Mutation policy

Only `artifacts/tests/c11d_d7/d7_3/` may change during the runner. No source, contract, matrix, seed registry, resolver, D3/D4/D5/D6 implementation, renderer, simulation, or C11-C content may be modified.

## Determinism

Repeated runs must generate identical canonical JSON and SHA-256 values.

## Negative tests

The checkpoint must reject invalid matrix/catalog authority, duplicate catalog keys or IDs, cross-domain seed bindings, runtime/renderer activation, `master_seed`, derivation activation, personalization/variation as seed sources, and protected C11-C semantics as seed authorities.

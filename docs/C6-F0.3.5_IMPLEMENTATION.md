## Runtime boundary

The implementation deliberately avoids a universal semantic `ContentDefinition` model.

```text
Domain-specific definition
        ↓
ContentRuntimeRegistry
        ↓
exact (kind, subtype) routing
        ↓
ContentRuntime
        ↓
content-specific runtime
        ↓
RenderedFrameStream
```

## Components

### `core/runtime/ContentRuntime.gd`

Common lifecycle abstraction. It owns routing-independent runtime state and exposes:

```text
initialize(definition)
is_initialized()
get_error()
get_current_frame()
is_finished()
get_frame_count()
get_fps()
get_rendered_frame_stream()
next_frame()
```

It contains no dependencies on `SimulationResult`, `WinningFrameDetector`, RNG, `ChallengeMechanic`, `PresentationUI`, CTA components, FFmpeg or exporter internals.

### `core/runtime/RenderedFrameStream.gd`

Logical/render-ready ordered frame stream. Each frame has:

```text
frame_index
payload
```

The stream validates identity, positive FPS, contiguous indices and payload presence. It stores neither raster pixels nor encoded video bytes.

### `core/runtime/ContentRuntimeRegistry.gd`

Routes by exact:

```text
(kind, subtype) → factory
```

Fail-closed behavior includes rejection of missing/empty routing metadata, duplicate routes, invalid factories, non-`ContentRuntime` factory results, unknown routes, and failed runtime initialization.

The visual schema intentionally leaves `subtype` open. Therefore the registry has no wildcard or implicit default visual route.

The default registry covers the current Challenge mechanic IDs through internal routing descriptors:

```text
key
parking
pilot
parking_v2
hit_v1
catch_v1
find_v1
choose_v1
count_v1
```

This does not alter the `ContentEnvelope` contract.

### `core/runtime/ChallengeRuntime.gd`

Boundary adapter over the existing sovereign Challenge pipeline. It may internally consume Challenge-only concepts but exposes only `ContentRuntime` and `RenderedFrameStream` semantics to the generic layer.

No Challenge simulation architecture was refactored by this change.

### `core/runtime/VisualLoopRuntime.gd`

Independent visual runtime based on `VisualLoopTimeline`. It emits logical visual state including loop frame/iteration, generator, layers and declarative loop configuration.

No Challenge score, winning-frame, phase, mechanic or RNG semantics are introduced.

### `core/runtime/VisualDrillRuntime.gd`

Independent visual runtime based on `VisualDrillTimeline`. It emits schema-defined exercise state together with monotonic frame/progress information.

No speculative phases are introduced.

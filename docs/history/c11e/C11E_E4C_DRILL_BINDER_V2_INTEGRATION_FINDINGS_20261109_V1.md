# E4C Drill V2 Binder Integration Findings — V1 (2026-11-09)

## Findings

1. The project already contains D9 dynamic request payload binder V2, with a strict 20-selector Drill matrix and a 67-source lineage. Do not build another binder.
2. E1 production service had only a populated Visual Loop boundary branch. This increment adds the `visual_drills` branch, consumes the existing V2 binder chain and seals a non-rendering Drill preparation boundary.
3. Producer GUI now consumes the E1 Drill preparation object (bridge, adapter envelope, stage contract and V2 binding preview); it does not rebuild the D9.10 or V2 chain. CLI uses the same E1 service.
4. E1 boundary verifies native phase source markers, END_CTA header ownership, exact family/tier schema and native Drill family music profile identity. It does not run Godot, audio, FFmpeg, the C11-C launcher or media.
5. Tests cover all 20 type/tier pairs, seed isolation, repeatability, wrong tier/seed and tamper cases, CLI route and GUI source contract.

## Dependency lineage issue

V109's D9.8 universal editorial model and resolver are newer than the hashes referenced by four dependent D9.9/D9.10 contract files. Four contracts are updated to current exact hashes. The A.3 Loop/Drill field-window proposal is not changed because its approved source lineage now points at the previous review-manifest hash. Its test reports one source SHA mismatch while the other 21 tests pass. This is a real visual-consumer blocker; do not silence it or overwrite an approved proposal.

## Audio seed isolation

The protected C11-C Drill launcher routes its `$Seed` to its internal audio generator when audio is enabled. It remains unchanged. E4C must use its `-NoSound` mode for visual capture and separately invoke the same native C11-C `FAMILY_MUSIC_V4` helper using `request.music_seed` and the canonical Drill type profile. This design needs its own future A/V integration gate; no audio was generated by this increment.

## Acceptance boundary

Isolated local test passes do not constitute active Windows acceptance. Actual Godot 4.7.1 V2 materialization is a dedicated Windows run (20 pairs × two independent executions). Even after that passes, D visual consumption and E4C A/V remain blocked pending current policy lineage and the separate visual/audio gates.

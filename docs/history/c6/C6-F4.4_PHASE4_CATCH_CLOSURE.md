## Root cause found during Phase 4

The first failing CATCH implementation produced mathematically correct simulation data but left:

`SimulationResult.is_self_scored == false`

The CATCH contract explicitly makes the mechanic mathematically sovereign: it owns `winning_frame`, `minimum_distance` and `score`. Consequently the generic winning-frame detector must not replace those values.

The failure signature was:

- winning frame: `158`
- minimum distance: `27.2707214355469`
- close calls: `8`
- score: `0.39398396809896`
- validation: `false`

The diagnostic run proved that setup, RNG context, simulation and contract validation were all correct. The decisive difference after the fix was:

`is_self_scored = true`

With that flag restored, the same legacy fixture succeeded on the first attempt and the validator remained the common validation gate.

## Regression lesson

Families that calculate their own winning result must carry their sovereignty flag all the way into `SimulationResult`.

This is now a mandatory audit item for every remaining self-scored family:

1. Does the mechanic calculate `winning_frame` itself?
2. Does it calculate `minimum_distance` / `score` itself?
3. Must `WinningFrameDetector` be bypassed?
4. Is `is_self_scored` explicitly asserted by the dedicated test?
5. Does legacy oracle equivalence preserve the same flag and metrics?

This rule must be checked before promoting future mechanics to native Canonical V2.

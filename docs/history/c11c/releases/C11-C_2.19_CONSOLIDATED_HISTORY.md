# C11-C 2.19 — Consolidated Historical Lineage

This document is the single historical record for the 2.19 patch/consolidation branch. It explains why prior revisions exist without allowing them to compete with the active 2.19.6 authority.

## 2.19.0
Restored the proven temporary AVI Movie Maker route used by the single Visual Drill Producer.

## 2.19.1
Corrected social hook lookup to the canonical `profiles/presentation/c11c_visual_hooks.json` bank rather than the obsolete authoring JSON path.

## 2.19.2
Aligned Art Direction hygiene and Visual Drill capture contracts with the AVI implementation. A later freeze claim was invalidated when workstation acceptance exposed additional inconsistencies.

## 2.19.3
Consolidated the duration-policy repair, C11-A.1 factory isolation, longform source-artifact test, C10-C QA-mode duration exemption, acceptance-root rotation, Art Direction script restoration and related acceptance glue.

## 2.19.3-v2
A global `System.Threading.Mutex` experiment was introduced as an attempted concurrency fix. It was rejected because it serialized capture and therefore violated the `Workers=7` requirement. It must never be revived.

## 2.19.4
Replaced the mutex approach with one temporary Godot project root per concurrent worker. Each worker owned its own override and generated Godot state.

## 2.19.5
Consolidated the worker test lifecycle (`_initialize()`), removed any Movie Maker mutex, repaired PowerShell `${i}:` interpolation, normalized Suite launchers and consolidated the active documentation/context surface.

## 2.19.6
Workstation acceptance exposed a fresh-worker failure: source `.godot` was excluded (correct for isolation), but the worker then lacked Godot's generated `global_script_class_cache.cfg`. `UnifiedSocialFrame.gd` could not resolve `PresentationProfile`, causing parse-error logs and gray/empty review frames even though Movie Maker recorded frames. The repair is one headless Godot editor bootstrap per worker before captures, with explicit cache and `PresentationProfile` verification. Initialization is sequential; captures remain concurrent.

## Disposition

- 2.19.0–2.19.5: historical / absorbed.
- 2.19.3-v2 mutex experiment: rejected / prohibited.
- 2.19.6: active final repair candidate, **not frozen until Windows/Godot acceptance passes**.

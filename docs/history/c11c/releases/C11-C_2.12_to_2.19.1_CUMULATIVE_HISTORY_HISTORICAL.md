# C11-C 2.12.0 → 2.19.1 — Cumulative History and Final Transition Record

## Purpose

This document is the historical bridge from the C11-C 2.12.x line through the final functional C11-C 2.19.1 freeze. Individual release documents preserve their original state; this file records how later patches accumulated and which historical states were superseded.

**Final functional source of truth:** C11-C 2.19.1.

**Absorbed maintenance:** 2.19.2 contains test-contract alignment only. It is absorbed into the frozen source tree so the executable contract corpus matches the already-working 2.19.1 runtime; it is not a new runtime/product baseline.

## 2.12.0 — Hooks / Social / Music / Production

- subtype coverage validates technical `grammar_id` against requested subtype;
- `scalar_potential` topology added to Invisible Forces;
- explicit grammar selection added to Visual Loop production launchers;
- technical → artistic → production naming documented;
- 27-slot weekly and monthly production workflows added with stratified/unique seeds;
- Spanish-safe social Unicode sanitation strengthened;
- FAMILY_MUSIC_V4 advanced to revision 4.1.1 with loop-safe cyclic noise, low-pass modulation and stronger profile identity.

C11-B, C7 and C9 boundaries stayed frozen.

## 2.13.0 — Regression / Duration / Seeds / Longform

- `tests/run_all.py` rejects explicit FAIL markers;

- physical checks derive frames from resolved duration rather than a 540-frame assumption;
- stratified seed allocation and minimum-gap validation expanded to weekly/monthly/multi-seed flows;

## 2.14.0–2.14.1 — Longform contract closure

- Longform source/composition contracts and tests were repaired and closed;

The five technical families were consolidated one-to-one with their artistic/production names:

## 2.16.0–2.16.3 and final freeze

The 2.16.x line was a post-2.15.1 art/tooling refinement line:

- 2.16.1 repaired contract registration, separator visibility and no-black Longform transition enforcement;
- 2.16.2 repaired resumable review seed parameter binding and refined Header/Footer editorial spacing/scale;

These states are historical snapshots. They are superseded by later C11-C production/Suite work and ultimately by 2.19.1.

The 2.17 line introduced the historical Challenge production adapter and centralized delivery-profile handling without copying mechanics into the Producer.

Key milestones included:

## 2.18.0 — Producer/Suite stabilization

The Producer GUI and Suite moved toward an explicit operator surface. Variation controls, queue state, completed-product detection, delivery-profile alias resolution and AAC 48 kHz stereo handling were stabilized. Active delivery profiles became explicit about FPS, encoder/CRF/preset and GOP settings.

## 2.18.2 — Longform REVIEW_720 same-path safety

The review production wrapper stopped attempting a same-path `Copy-Item` when source and destination were already identical. `C11CProductionReviewCopySafetyTest.gd` protects this regression.

## 2.18.4 — Drill duration/test contract alignment

The current Drill envelope was made explicit in contracts:

- Tracking: 3 s PRE_ROLL + 21 s GAME + 3 s END_CTA = 27 s / 810 frames;
- Saccade/Pursuit/Peripheral: 3 s + 17 s + 3 s = 23 s / 690 frames.

The canonical Suite runner also required SceneTree/MainLoop contract tests to terminate explicitly with `quit(0)` / `quit(1)`.

## 2.18.5–2.18.6 — Freeze-candidate and platform-layout groundwork

2.18.5 prepared the final C11-C manufacturing freeze candidate. 2.18.6 corrected the current Drill duration default to 17 s for non-Tracking families, repaired the Longform source-artifact contract and introduced the D1.5 versioned declarative platform-layout template roadmap.

## 2.18.7 — Producer AVI wait hotfix

A stable-file wait was added around the Producer Movie Maker AVI capture attempt. Windows runtime subsequently showed that the problem was not solved by waiting alone.

## 2.18.8 — C11-A.1 factory isolation

The historical Challenge 005 run exposed a project-wide `override.cfg` leak affecting resolution expectations. 2.18.8 isolated/quarantined the override around each historical factory execution and added `C11A1FactoryIsolationContractTest.gd`.

This repaired the historical batch without modifying simulation truth. The final C11-A.1 matrix later completed at 54/54 PASS.

## 2.18.9 — OGV experiment (superseded)

The single Drill Producer was temporarily moved from AVI to OGV to avoid the earlier AVI timeout. On Windows, OGV generation completed but FFmpeg received an unusable/incomplete container (`End of file`). The experiment was abandoned.

The frozen implementation does not depend on OGV or PNG-sequence capture.

## 2.19.0 — Proven temporary AVI capture route restored

The single Drill Producer returned to temporary AVI and was aligned byte-for-byte in invocation structure with the proven review runner:

```text
Start-Process Godot
--path .
--scene core/presentation/rendering/VisualContentPlayer.tscn
--definition=<resolved envelope>
--write-movie=<temporary .avi>
--fixed-fps 30
--quit-after <total frames>
```

The route uses no explicit `--resolution` CLI argument, waits for AVI stabilization, converts video-only AVI to silent source MP4, and muxes generated family music afterwards. AVI is scratch-only.

## 2.19.1 — Social-hook schema repair / final functional release

The successful 2.19.0 capture exposed a separate PowerShell schema mismatch: the Producer attempted to read `authoring.json.content.hook`. The authoritative hook source was already `profiles/presentation/c11c_visual_hooks.json`.

2.19.1 changed only the editorial sidecar selection:

- read the canonical hook bank;
- resolve the family hook set;
- apply the established deterministic seed + family-offset selection rule;
- preserve the AVI capture and delivery pipeline unchanged.

Windows smoke then reached:

```text
[C11-C-PRODUCER-DRILL] FINAL PRODUCT PASS
```

## 2.19.2 — absorbed test-only maintenance

Two contracts were found still describing the superseded OGV path or checking `--path .` with a brittle literal. The contracts were aligned with the working 2.19.1 implementation.

No runtime/product implementation changed.

## Final C11-C closure

The final frozen source tree is identified functionally as **C11-C 2.19.1**. The absorbed 2.19.2 corrections exist only to make the executable test corpus faithfully describe the final implementation.

The D branch starts from this exact state. Historical C11-C snapshots remain immutable evidence and recovery material; they do not override the 2.19.1 freeze.

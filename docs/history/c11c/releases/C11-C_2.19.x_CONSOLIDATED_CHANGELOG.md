# C11-C 2.19.x — Consolidated Release History

This document is the single historical summary of the 2.19 repair branch. Older notes remain evidence; they are not operational authorities.

## 2.19.0 — AVI capture restoration

The 2.18.9 OGV experiment produced an FFmpeg end-of-file failure in the workstation route. The active review/Producer capture path was returned to the proven temporary AVI workflow followed by FFmpeg packaging. OGV is historical only.

## 2.19.1 — social hook schema repair

Producer social metadata was corrected to read the canonical C11-C visual hook bank. The stale assumption that `authoring.json.content.hook` was the authoritative location was removed from the active route.

## 2.19.2 — contract alignment

Art Direction production-hygiene and Visual Drill Movie Maker contracts were aligned with the actual AVI invocation. A 2.19.2 freeze was declared at one point, but later workstation acceptance exposed additional defects; that freeze declaration is therefore superseded historical state.

- C11-A.1 factory isolation around `override.cfg`;
- Visual Drill duration policy alignment: 17s default gameplay, 21s tracking gameplay;
- Longform source-artifact contract assertion repair;
- restoration of the valid 359-line Art Direction batch PowerShell source after parser corruption;
- QA-mode exemption for the deliberately short C10-C physical smoke fixture;

## 2.19.4 — suite consolidation

The workstation reported `c11c-suite 0.1.4 + Producer 0.9.7 + C11-C 2.19.4 consolidated contracts STATIC PASS`. New review-contract tests and launcher verification were introduced around the parallel Art Direction and Visual Drill review-envelope paths.

Two defects then became visible on direct workstation execution:

1. the parallel-review worker-isolation contract could block the console because the test itself was too close to the process/render layer;
2. the Visual Drill review-envelope contract had the same class of problem when executed as a direct suite test.

A launcher verifier also reported that the compatibility typo launcher `c11c-maintenace` did not delegate to canonical `c11c-maintenance`.

## 2.19.5 — consolidated repair candidate

The final 2.19.x repair candidate resolves those defects together with the original parallel Movie Maker race.

### Parallel worker ownership

The root cause of the observed 540x960 fallback during a 720x1280 `Workers=7` Art Direction batch was concurrent mutation of the one project-root `override.cfg`. The correct solution is not serial execution.

The parent batch now:

- creates one 720x1280 override;
- sets `C11C_SHARED_MOVIE_OVERRIDE=1`;
- launches the same real `Start-Job` workers as before;
- lets each worker inherit the shared-override flag;
- prevents worker-side `Enter/Exit-C11CMovieOverride` from touching the root file;
- restores the override once, after all selected stages finish.

Worker artifacts remain isolated by family/grammar/seed and explicit authoring paths.

### Test isolation

The parallel-worker and Visual Drill envelope tests are source-only contract tests. They use `FileAccess` to inspect the orchestration sources and must not launch render processes.

### Launcher hardening

The direct test launcher now delegates through a bounded Python runner with a 120-second timeout. This converts an indefinite hang into a deterministic timeout/exit code while preserving ordinary Godot test execution.

Canonical `c11c-suite` launchers were normalized, and the typo-path maintenance launcher now delegates to canonical `c11c-maintenance` with exit-code propagation.

### Retired Studio policy

`c11c-studio` is retired legacy material and is outside the active 2.19 toolchain. It is not updated by 2.19.5.

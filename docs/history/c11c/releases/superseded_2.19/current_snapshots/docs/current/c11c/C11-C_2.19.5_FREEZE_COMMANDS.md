# C11-C 2.19.5 — Freeze Commands

This procedure is the only path from the final repair candidate to a 2.19.5 C11-C freeze. Do not create a freeze receipt manually.

Extract the consolidated repair ZIP at the repository root, then:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\maintenance\consolidate_c11c_2_19_documentation.ps1

python .\c11c-suite\self_test.py
python .\c11c-suite\c11c-producer\self_test.py
```

## C. Prove real seven-worker concurrency

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\prototypes\c11c_bulk\run_c11c_art_direction_batch_v4.ps1 `
  -Workers 7 `
  -Loops `
  -Reset
```

Required terminal evidence:

```text
[C11-C-WORKER] observed_concurrency=2
...
[C11-C-WORKER] MAX_OBSERVED_CONCURRENCY=<value greater than 1>
```

Every capture must report 720×1280. A one-at-a-time run is not a pass.

## D. Full acceptance

```powershell
python .\tests\run_all.py
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\FULL_ACCEPTANCE_C11C_2.19.5.ps1
```

The full acceptance script validates the worker concurrency manifest and refuses completion when concurrency is not proven.

## E. Final C11-C freeze seal

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\c11freeze\finalize_c11c_2_19_5_freeze.ps1
```

Expected terminal marker:

```text
[C11-C-FREEZE] FINAL SEAL PASS
```

The seal writes:

- `artifacts/releases/c11-c/C11-C_2.19.5_FROZEN_MANIFEST.json`
- `artifacts/releases/c11-c/C11-C_2.19.5_FREEZE_RECEIPT.md`
- `artifacts/releases/c11-c/C11-C_2.19.5_FROZEN.zip`
- matching `.sha256`

After the seal, update no code. Any future work starts from the frozen package and a new checkpoint/version.

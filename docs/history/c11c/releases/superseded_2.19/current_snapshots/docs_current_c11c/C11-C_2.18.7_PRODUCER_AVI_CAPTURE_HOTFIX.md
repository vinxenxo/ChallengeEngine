# C11-C 2.18.7 — Producer Visual Drill AVI Capture Handshake Hotfix

## Symptom

The single-Visual-Drill Producer runner could report `Godot did not create AVI` immediately after Godot returned, while the rendering pipeline itself was otherwise healthy.

## Root cause

The runner checked the Movie Maker AVI path immediately after the Godot process returned. The broader C11-C review runner already protected this boundary with a wait-for-stable-file handshake; the Producer single-Drill runner did not.

A second robustness issue was that the render path hard-coded `godot` even though the generator path had already resolved the executable through `GODOT_BIN` when provided.

## Repair

- Added `Wait-ForStableFile` to the single-Drill Producer runner.
- The AVI is now required to exist and remain non-zero/stable before FFmpeg conversion.
- The render step uses the same resolved `$godotExecutable` as the generator step.
- Producer product retention semantics remain unchanged: the AVI is intermediate by default and is copied into the product only with `-KeepAvi`.
- No mechanics, RNG, authoring truth, timing policy, rendering implementation or frozen C11-B contract was modified.

## Regression coverage

The existing `C11CArtDirectionProductionHygieneContractTest.gd` now asserts the AVI stabilization handshake and consistent Godot executable usage. Producer self-test and GUI contract checks were updated for Producer 0.9.3.

## Validation

Static validation completed in the build environment for Python syntax, JSON parsing and source-contract assertions. Windows/Godot 4.7.1 runtime validation remains the project-side execution gate.

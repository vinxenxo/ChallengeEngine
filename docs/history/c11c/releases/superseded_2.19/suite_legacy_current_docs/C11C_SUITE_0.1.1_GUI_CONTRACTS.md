# C11-C Suite 0.1.1 — GUI Contracts

## TEST

Runs canonical project test entry points and individual registered `KNOWN_SUITES` entries. It does not contain a second implementation of the tests.

## CATALOG

Reads `artifacts/` recursively and presents generated evidence/products. Preview and inspection are read-only.

## MAINTENANCE

Executes bounded maintenance actions. Automatic deletion is restricted to explicitly safe transient roots; repository and delivery validation call canonical scripts. Project ZIP generation excludes transient developer data and excludes `artifacts/` by default.

## CONFIG

Provides low-level inspection of declared challenge, definition, delivery, schema and contract surfaces. JSON is validated before write and an adjacent `.bak` is created before editable configuration is saved. Runtime/code files are read-only.

## PRODUCER

The existing Producer remains the audiovisual orchestration surface. Its move into `c11c-suite/c11c-producer/` is a filesystem/UI reorganization; production wrappers remain canonical.

## Non-negotiable boundary

None of the five GUIs may implement or duplicate gameplay mechanics, structural RNG, simulation truth, `SimulationResult`, `winning_frame`, `RenderedFrameStream`, audiovisual ownership or renderer mathematics.

## Addendum 0.1.2 — launcher parity

`c11c-test` provides both GUI and console launchers. New registered `*Test.gd` suites are discovered from `tests/run_all.py`; operational PS1 runners that are part of the Suite contract must also be represented in `C11_COMMANDS`.

## Addendum 0.1.2 — launcher parity

`c11c-test` dispone de lanzadores GUI y consola. Las suites `*Test.gd` nuevas se descubren a partir de `tests/run_all.py`. Los runners PS1 que forman parte de la superficie operativa deben tener también un comando equivalente en `C11_COMMANDS`.

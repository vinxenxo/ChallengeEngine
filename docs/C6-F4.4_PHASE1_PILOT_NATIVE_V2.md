# C6-F4.4 — Phase 1: Pilot Native Canonical V2

## Objective

Promote `pilot` to consume the certified F1.1 Canonical V2 directly in the effective runtime, while preserving full backward compatibility for the remaining legacy mechanics.

## Scope

- `PilotMechanic.setup()` reads mechanical parameters from `simulation.parameters`.
- Legacy V1 fallback remains available when `simulation.parameters` is absent.
- `ChallengeExecutionPipeline` accepts Canonical V2 `simulation.seed` / `simulation.rng_version` without requiring `generation`.
- `ChallengeExecutionPipeline` and `ChallengeTimelineBuilder` accept the Canonical V2 inline `video` dictionary while preserving profile-ID compatibility.
- `ChallengeRuntimeBridge.run_effective_pipeline()` bypasses the V1→F3 compatibility projection only for `pilot`.
- All other legacy mechanics continue through the certified F4.3 projection.
- The Legacy Runtime Oracle remains unchanged and continues to provide the cross-runtime equivalence gate.

## Frozen invariants

No changes are made to:

- RNG implementation or stream definitions.
- Pilot simulation mathematics.
- `SimulationResult`.
- `WinningFrameDetector`.
- `VideoTimeline` semantics.
- Presentation binding semantics.

## Native V2 invariant

For `pilot`, the effective runtime input must:

1. contain `simulation.seed` and `simulation.rng_version`;
2. contain `simulation.parameters` with all mechanical pilot parameters;
3. contain the Canonical V2 `video` dictionary;
4. not contain a legacy `generation` section;
5. not restore mechanical `difficulty.tolerance` or mechanical `content.*` fields at the root.

## Acceptance gate

The dedicated `C6F4CanonicalV2PilotTest` must prove:

- pure migrated Canonical V2 executes directly;
- the effective runtime uses the same pure V2 input for pilot;
- timeline construction succeeds from the inline V2 video dictionary;
- direct/effective results remain equivalent to the legacy oracle;
- frame count and winning frame remain equivalent.

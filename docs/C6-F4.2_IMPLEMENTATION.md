# C6-F4.2 — Shadow Runtime Integration

## Objetivo

Integrar de forma side-by-side el pipeline C6 construido en F1.1 + F3.1 + F3.2 + F3.3 con el runtime legacy sin cambiar la ruta de render existente.

## Flujo

```text
Legacy V1 JSON
    |
    +--> runtime legacy actual --------------------+
    |                                              |
    +--> F1.1 migrate_legacy_v1_to_v2              |
             |                                     |
             +--> F4 transient F3 projection       |
                      |                            |
                      +--> F3.1 Simulation --------+
                      |                            |
                      +--> F3.2 Timeline ----------+--> Equivalence Gate
                      |                            |
                      +--> F3.3 Presentation ------+
```

## Reglas de seguridad

- El `ChallengeRuntimeContext` es exclusivamente un contenedor de datos.
- F1.1 no se modifica.
- La configuración canonical V2 producida por F1.1 no se muta.
- La adaptación a F3 se realiza sobre una copia transitoria.
- No se registra ningún perfil dinámicamente.
- El puente no contiene matemática de mecánicas ni lógica RNG.
- El seed utilizado por la ruta Shadow es el `seed_used` elegido por el runtime legacy, para comparar la misma realización determinista.
- Los perfiles `f4_legacy_*` son archivos estáticos y solamente reproducen la temporalidad declarada de los fixtures legacy.
- `fam_garage_01` es metadata de identidad; no cambia ni carga los assets físicos.

## Gate

Se comparan:

- FPS y los cuatro bloques temporales.
- `total_frames`.
- `SimulationResult.winning_frame`.
- cantidad de `FrameSnapshot`.
- posición, rotación, escala y opacidad de cada snapshot.
- `custom_data` completo de cada snapshot, de forma recursiva.

El gate es fail-closed y se ejecuta antes de continuar con assets/render.

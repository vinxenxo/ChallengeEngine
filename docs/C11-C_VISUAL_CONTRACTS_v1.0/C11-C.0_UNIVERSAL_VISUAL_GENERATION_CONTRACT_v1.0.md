# C11-C — UNIVERSAL VISUAL GENERATION CONTRACT v1.0

**Project:** ChallengeEngineV01_STATELESS  
**Checkpoint:** C11-C  
**Status:** APPROVED AS FAMILY BASELINE / CLOSED FOR FAMILY PROTOTYPING  
**Scope:** presentation, procedural art direction and visual QA only

## 1. Purpose

C11-C defines the visual language for the mathematically generated `Visual Loop` families and the perceptually functional `Visual Drill` families. It extends the frozen C11-B social frame without modifying simulation, RNG, challenge logic or existing frozen contracts.

The product principle is:

> **Mathematical visuals are generated from deterministic rules, not from pre-rendered art assets.**

## 2. Hard Architectural Boundary

### Allowed

- procedural visual generators;
- isolated renderers/shaders/helpers;
- family-specific mathematical models;
- family-specific visual configuration;
- prototype-only visual QA tooling;
- procedural effects required to realize the approved art language.

### Frozen / forbidden

Never modify to satisfy art direction:

- `SimulationResult`;
- simulation mechanics;
- simulation RNG streams;
- `WinningFrameDetector`;
- `WinningFrameVisibilityGate`;
- `RenderedFrameStream` contract;
- C7 audiovisual contracts;
- C9 authoring contracts;
- C11-B `UnifiedSocialFrame`;
- Header/Body/Footer geometry;
- challenge mechanics/assets.

## 3. Frozen Social Frame

Physical canvas: `540 × 960 px`, target `30 FPS`.

- Header: `y=0..144`
- Body: `y=144..816`
- Footer: `y=816..960`
- Body: `540 × 672 px`
- Optical centre: social `(270,480)` / Body-relative `(270,336)`

Family content must respect the existing Body coordinate contract. No family may redefine the social frame.

## 4. Visual Signature

All families should share:

1. deep non-black backgrounds;
2. restrained, data-driven palettes;
3. precise geometry;
4. controlled luminance/bloom;
5. intentional temporal motion;
6. depth by structure, opacity, scale and trails rather than photographic assets;
7. high contrast where perception requires it;
8. no gratuitous rainbow gradients;
9. deterministic output for equal `(seed, time, config)`.

## 5. Determinism Contract

For a fixed configuration and seed `S`, the visual state is a pure function of seed and normalized temporal position:

`V = F(S, u, config)`

where `u` is deterministic frame position.

The runtime MUST NOT introduce:

- wall-clock randomness;
- `randf()` or equivalent non-seeded entropy;
- frame-order-dependent mutable randomness;
- unseeded noise;
- hidden state that changes visual output across repeated renders.

Repeated renders with identical `(S, config, FPS, duration)` must produce the same visual frames up to encoder-level differences explicitly documented by the export pipeline.

## 6. Temporal Contract

Canonical visual benchmark: `10.0 s`, `30 FPS`, `300-frame period`.

For normalized time `u ∈ [0,1)` all cyclic quantities must close mathematically:

`P(0)=P(1)`

and, for primary animated quantities:

`P'(0)=P'(1)`

Preferred construction: periodic harmonic bases with integer temporal frequencies. No seam correction, first-frame duplication or end-of-loop reset is allowed.

## 7. Art-vs-Function Rule

### Visual Loop

Beauty is a first-class acceptance dimension. Mathematical structure, composition, rhythm, light and transformation must be visually compelling.

### Visual Drill

Perceptual function is first. Aesthetic treatment may improve engagement and coherence only while preserving stimulus salience, target discriminability, timing and test validity.

## 8. Renderer Independence

A family is a **generative specification**, not a shader. It may be realized by one or more shaders, CPU-generated geometry, draw calls, particle systems, vector primitives or combinations thereof.

## 9. Universal Banned List

- pre-rendered visual assets as the generative core;
- AI-generated textures used as the mathematical visual source;
- uncontrolled rainbow cycling;
- stroboscopic flicker;
- random jitter without perceptual purpose;
- sustained drift from the intended optical centre;
- uncontrolled bloom that destroys edge information;
- visual clutter that masks the intended stimulus;
- frame-order-dependent randomness;
- modifications to frozen simulation architecture for cosmetic reasons.

## 10. Universal Acceptance Layers

Every family is evaluated in four layers:

1. **Contract:** configuration and architectural compliance.
2. **Determinism:** repeated identical inputs produce identical frame state.
3. **Physical render:** 540×960 / 30 FPS export is valid and visually contained.
4. **Human visual review:** the artifact actually communicates the intended family identity.

No family becomes product-ready because only the automated gates pass.

## 11. Family Prototype Rule

Each new family starts with one canonical seed and one physical render. The GIF is the primary visual inspection artifact; MP4 is the production-oriented reference artifact; the manifest is the technical evidence.

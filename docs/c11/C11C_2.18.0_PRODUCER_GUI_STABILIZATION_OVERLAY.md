# C11-C 2.18.0 — Producer GUI + Production Stabilization Overlay

## Apply over

Current C11-C Producer state after 2.17.9 / delivery-profile stabilization.

## Purpose

Finish the GUI working surface and remove the remaining production-wrapper regression visible from A LA CARTA runs.

## UI changes

- Remove visible banner/header.
- Remove visible help/advice copy from the working area.
- Compact dark cyberpunk palette with cyan/magenta accents.
- Variation controls become visual sliders plus `ALEATORIO` checkbox. Random is the default; fixed sliders activate only when `ALEATORIO` is disabled.
- Queue selection has a strong selected-row treatment.
- Completed rows remain visible and are dimmed.
- Existing manually-seeded products can appear as `YA PRODUCIDO` only when a manifest matches the requested delivery profile; they are not added to the runnable queue unless `FORCE` is checked.
- Failed recipes remain visible as `ERROR` and can be retried.

## Production fixes

- Central delivery profiles now carry an exact target `fps`, encoder, CRF/preset and GOP frame count.
- Visual Loop production resolves delivery aliases and no longer assumes an undeclared `.fps` property.
- Visual Drill production resolves aliases and targets 48 kHz stereo AAC at source mux.
- Delivery wrappers use central encoding parameters rather than hard-coded output quality where applicable.

## Important runtime contracts

- Challenge source capture remains native 540×960.
- Visual Loop and Visual Drill review capture remains the proven 720×1280 C11-C path.
- Delivery scaling occurs after source capture.
- `MASTER_1080` is the standard default delivery profile.
- No Challenge mechanics, RNG, simulation truth, `SimulationResult`, `winning_frame`, `close_calls`, `WinningFrameDetector`, `RenderedFrameStream`, C7, C9 or C11-B logical 540×960 semantics are changed.

## Validation

Static validation performed in the build environment: Python compilation succeeds; changed PowerShell files have balanced block/parenthesis structure; delivery profile JSON parses; GUI source contains slider, queue-state and cyberpunk styling paths.

Windows/Godot runtime acceptance remains the final gate because this environment does not host the user's PySide6 desktop runtime or Godot project execution context.

# C11-C 2.13.2 — Native stderr + AVI hygiene repair

## Incident

Windows PowerShell 5.1 runs the Visual Loop launchers with `$ErrorActionPreference = Stop`. Godot 4.7.1 emits the low-disk-space warning on native stderr. PowerShell promoted that non-fatal warning to `NativeCommandError` at the `godot ... | Tee-Object` pipeline and aborted before the launcher could validate the real process exit code.

At the same time, the Movie Maker `.avi` capture is an intermediate artifact and the previous launcher did not remove it after publishing the MP4/GIF. Those captures can consume multiple GiB per product.

## Repair

Patched all five Visual Loop `run_prototype.ps1` launchers:

1. Temporarily set `$ErrorActionPreference = Continue` only around the native Godot capture pipeline.
2. Keep the full Godot output in the existing log.
3. Capture and validate the actual `$LASTEXITCODE`.
4. Restore the previous error preference immediately.
5. Remove the intermediate `.avi` in `finally`, including after failed runs.

## Boundaries

No changes to simulation truth, renderers, mechanics, C7 audio ownership, presentation contracts, seeds, family nomenclature, or final MP4/GIF/audio/social outputs.

## Operational requirement

The low-disk-space warning was genuine. Free substantial disk space before resuming the corpus. The repair stops a warning from being misclassified as process failure; it does not make a full disk safe.

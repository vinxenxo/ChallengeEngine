# C11-C 2.19.0 — Producer AVI Capture Route Repair

## Status

HOTFIX / CANDIDATE — restores the already-proven C11-C Visual Drill Movie Maker capture path after the 2.18.9 OGV route produced a truncated container (`FFmpeg: End of file`).

## Diagnosis

The canonical `run_c11c_visual_drill_review.ps1` runner successfully uses Movie Maker with a temporary AVI, `Start-Process`, `--path .`, the active `override.cfg`, and no explicit `--resolution` CLI override. The single Producer had diverged from that path.

## Repair

The single Visual Drill Producer now mirrors the proven invocation:

1. `Enter-C11CMovieOverride` establishes the 720×1280 source envelope.
2. Godot is launched via `Start-Process` with `--path .`.
3. Movie Maker writes a temporary AVI in the scratch directory.
4. The runner waits for the AVI to stabilize.
5. FFmpeg converts video-only from AVI to H.264 MP4.
6. Audio generation/muxing and delivery profiling remain unchanged.
7. Scratch cleanup removes the AVI after the run.

## Product policy

AVI is an implementation detail. The Producer has no `-KeepAvi` option and publishes no AVI product artifact.

## Scope boundary

No mechanics, simulation, RNG, timing truth, `winning_frame`, C11-B contract, or logical 540×960 geometry changes.

## Verification

Static validation: Producer self-test, Producer GUI contract, Suite self-test and the dedicated Movie Capture contract are checked in the build environment. Windows/Godot 4.7.1 runtime is the operator gate.

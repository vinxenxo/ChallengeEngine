# C11D_SHARED_PRODUCTION_GUI_DYNAMIC_CATALOG_OVERLAY_V1

Aditive overlay: adds a read-only dynamic catalog API/CLI for future GUI cascading selectors. It consumes `universal_editorial_model.build_catalog()` and the canonical GUI state / D9.9 contracts. Family/subtype/variant inventories are resolved at runtime and are not hard-coded.

Application: copy the ZIP into Downloads, then use the guarded copy/paste PowerShell block supplied in the conversation. That block validates the ZIP SHA-256, frozen C11-C manifest, all 8 source pins, 8 path/hash entries, collisions, and extracted hashes.

Primary test: `python -B .	ools\c11d\d9	est_shared_production_context_gui_catalog.py`

CLI examples:
- `python -B .	ools\c11d\d9\shared_production_context_gui_catalog.py --audit-only`
- `python -B .	ools\c11d\d9\shared_production_context_gui_catalog.py --catalog`
- `python -B .	ools\c11d\d9\shared_production_context_gui_catalog.py --families-for visual_loops --mode REVIEW`
- `python -B .	ools\c11d\d9\shared_production_context_gui_catalog.py --selectors-for visual_loops c11c_geometric_waves_v1 --mode REVIEW`
- `python -B .	ools\c11d\d9\shared_production_context_gui_catalog.py --resolve-selection visual_loops c11c_geometric_waves_v1 harmonic_membrane --mode REVIEW`

The contract does not enable media rendering or release. Longform remains disabled; Visual Loops/Drills remain REVIEW-only while their canonical catalog state says `ACTIVE_MODEL_ONLY` and `request_plan_compatible=false`.
